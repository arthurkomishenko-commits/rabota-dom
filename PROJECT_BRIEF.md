## 2. Платформа и инженерия (зафиксировано)
- Стек: Astro + Tailwind + GSAP (ScrollTrigger, SplitText). Полная статика. GitHub Pages + Actions. Репозиторий `rabota-dom`.
- i18n: `/` = иврит (RTL, prefixDefaultLocale: false), `/ru/`, `/en/`. Нативный роутинг Astro, автогенерация hreflang + `x-default` → `/`. Раздельные локализованные записи коллекций. `/admin` исключён из i18n-матрицы. 404 трёхъязычная (детект языка скриптом).
- Шрифт Rubik: self-host (@fontsource) + сабсеттинг unicode-range (≤40 КБ/сабсет).
- Темы: инициализация каскадом **localStorage → prefers-color-scheme → светлая**; ручной тумблер перезаписывает в localStorage (решение финальной приёмки: доступность).
- RTL: CSS logical properties / логические классы; направления анимаций — параметр (`rtlInvertX`), не хардкод; телефоны и числа в иврите — `dir="ltr"`.
- Медиа: pre-build скрипт sharp (raw → WebP/AVIF, responsive; бюджеты жёсткие, билд падает при превышении). Видео — YouTube через фасад (lite-youtube-embed). `content-visibility: auto` ниже фолда.
- **Worker (заявки + отзывы):** Telegram — **plain text без parse_mode** (эмодзи-структура; исключает инъекции и потерю лидов) · honeypot + time-check ≥2.5 с · KV rate-limit `RATE_LIMIT_KV` (5/час/IP) · CORS только наш домен · нормализация телефона (+972→0) + `^05\d{8}$` · обязательные поля: имя, телефон (город — optional) · метаданные лида: страница, язык, устройство · фото отзывов: **сжатие на клиенте** до ~1920px/≤1 МБ, до 3 шт, отправка в Telegram через `ctx.waitUntil()` (ответ клиенту сразу) · ответы 429/500 с текстами · рядом с формой всегда видимая кнопка «Отправить через WhatsApp» (в catch — `location.href`, не `window.open`).
- Контакты: телефон = WhatsApp = **972549731889**, WhatsApp Business подключён. Префиллы `wa.me` на языке интерфейса.
- Аналитика + Search Console — после первого деплоя. JSON-LD: LocalBusiness, Service, Product/CreativeWork на работы.

## 3. Структура сайта и главная
Страницы: `/` · `/portfolio` (+`/portfolio/[slug]`) · `/services` + `/pergolas` `/canopies` `/fences` · `/calculator` · `/map` · `/about` · `/contact` · `/accessibility` (הצהרת נגישות) · `/privacy` · 404.
**Главная — 10 экранов (mobile-first, каждый экран отвечает на один вопрос):**
1. Hero-гибрид: фоном сборка перголы, поверх — Владимир, гео, заголовок. Покадрово: 0–1 с столбы + портрет + «Владимир · Ноф-ха-Галиль»; 1–3 с балки, портрет сжимается, УТП-строка; 3–5 с тень + CTA. Сборка замирает на 85–90%. **CTA-иерархия: в hero 2 кнопки (WhatsApp + «Получить предварительную оценку»), телефон — вторичная текстовая ссылка у номера.**
2. Почему доверяют: фото на объекте + 3 конкретики (траст-формула · аккуратный монтаж и честные сроки · материалы под климат Израиля).
3. Последние проекты: 3 крупные свайп-карточки (фото, город, материал, срок) → «Все проекты». Показывается при ≥3 полных паспортах.
4. Видео процесса 20–30 с (фасад).
5. Как проходит работа: Связь → Замер → Изготовление → Монтаж.
6. До/После: ползунок, 3 объекта.
7. Мини-форма: имя + телефон + «Получить предварительную оценку»; «Ответим удобным для вас способом».
8. Принципы мастера (3 реальных).
9. FAQ-аккордеон (10 каркасов GPT; цена и гарантия — финализируются с данными).
10. Финальный CTA: крупное фото + WhatsApp / Позвонить / Оценка.
**Sticky-панель (мобайл, со 2-го экрана):** WhatsApp · Позвонить · Заявка — три равноправных канала («быстро спросить / обсудить сразу / оставить заявку»). Не перекрывает hero.
Формы: успех = экран благодарности на месте; возврат формы только по кнопке «Отправить ещё заявку»; 429 → «Слишком много попыток — попробуйте через час или напишите в WhatsApp»; 500 → сразу WhatsApp-ветка. Строка согласия на обработку данных. Тексты форм — по спецификации GPT-раунда 2.

## 4. Портфолио и контент-пакет
- Карточка-«паспорт объекта»: рамка 1px, фото 4:3 со «спилом» clip-path (зеркалится в RTL), тег материала, штамп: название + город + год (monospace) | метрики (площадь/длина, крепёж/профиль). Метрики — только реальные; нет данных → метрика скрыта. Фейки запрещены.
- Фильтры: тип / материал / город / до-после. Карточки — процессные кадры «до → каркас → финиш».
- «Живой чертёж»: десктоп hover 180 мс, мобайл — тап по иконке-угольнику; SVG-оверлей 0.92, габариты + 2–3 узла («анкер M12»); stagger 40–60 мс; деградация — статичный каркас + 3 строки габаритов. Ассеты без текста внутри — подписи из словарей (один комплект на 3 языка).
- Лайтбокс: все фото + hard_part + отзыв (если есть).
- **Контент-пакет объекта (минимум для публикации):** cover · ≥3 фото (из них ≥1 процесс или до/после) · тип · материал · город · год · срок · описание ≥2 предложений · ≥1 метрика · coords (огрублённые). Неполный объект не публикуется — Zod-гейт.
- Анти-шаблонные ходы услуг (тень 12/16/19, дождь-тест, «с улицы/со двора», «сколько лет стоит» и т.д.) — **только при наличии ассета, иначе блок скрывается целиком.**

## 5. Карта работ (`/map`)
- Leaflet (~42 КБ) + стандартные OSM-тайлы (в Израиле подписи — иврит; альтернатива CARTO — оценка на этапе 3). Инициализация по IntersectionObserver; при >15 точек — markercluster. Грузится только на странице карты (отдельный перф-профиль).
- Маркеры — круглые фото; hover — мини-карточка (фото 120×90, тип, район, строка отзыва); клик — попап-«паспорт» со всеми фото и отзывом.
- Приватность: координаты огрубляются при вводе (~±100 м) **плюс** jitter 50–100 м при рендере. Точный адрес не хранится нигде.
- Отзывы: форма (текст + до 3 фото, клиентское сжатие) → Worker → Владимиру в Telegram → одобрение → публикация. Клиенту: «Отзыв появится после проверки мастером». **Политика удаления:** по запросу клиента отзыв удаляется в ≤7 дней; прописано в `/privacy`.
- Тизер на главной: статичное превью + «Открыть карту работ».
- Добавление точки — обязательная часть процедуры закрытия объекта (протокол §12).
- **Гейт запуска: ≥6 точек; иначе /map и тизер скрыты из навигации.**

## 6. Калькулятор (`/calculator`)
- Astro-island; `rates.json` — **статический import в бандл** (не fetch). Две услуги (решение Артура): **пергола** и **забор** («навес» = опция покрытия перголы).
- Пергола: ширина × глубина (дефолт 4×3) → м² · материал дерево/алюминий/комбо [комбо] · покрытие ламели [деф.]/поликарбонат/сплошное · крепление к стене [деф.]/отдельностоящая · участок ровный [деф.]/уклон · **чекбокс «демонтаж старой конструкции»** · опции LED, водоотвод. Формула: base[материал] ₪/м² × S × коэффициенты + опции; минимальный заказ.
- Забор: длина (деф. 20 пог. м) · высота 1.2/1.5/1.8 [деф.]/2.0 · материал дерево/металл/комбо [деф.] · заполнение с просветами [деф.]/сплошное · калитка [деф. 1]/+ворота · рельеф. Формула: rate[материал][высота] × L × k + фикс.
- Guard-rails: вне min/max — цифры нет, показываем «Нестандартный проект — посчитаем вручную» + WhatsApp.
- UX: каждый шаг «досборивает» схематичный объект на превью; **результат — только после тапа «Показать ориентир»; первым — дисклеймер:** «Ориентир ±20%. Точная сумма — после бесплатного замера. Не является предложением. Не учитывает транспорт, подъём и подготовку площадки» + короткое «что чаще всего меняет стоимость». Префилл WhatsApp от лица клиента: параметры + «Ориентир с сайта, хочу уточнить после замера».
- **Статус ставок:** `rates.json.status: draft|production`. Пока draft — страница в режиме «в калибровке» и скрыта из меню. Перевод в production: цифры подтверждает Владимир → меняет Артур → запись в DECISIONS.md. Ориентир Артура: ₪1000/м² базы пергол (проверить единицу при калибровке).

## 7. Дизайн-система и OG
- Токены Gemini обеих тем; radius 2px «инженерная фаска»; кнопка «матовый алюминий» (5 состояний); инпуты с активной нижней линией; тег материала; фокус-кольца outline 2px accent + offset 2px на всех интерактивах.

- Лого: RABOTA DOM латиницей (Rubik Medium, caps, ls 0.05em) + дескриптор **פתרונות מתקדמים בעץ ואלומיניום**; SEO-строка פרגולות, חיפויים וגדרות — в мета.
- Типографика иврита: база 18px (ru/en 16px), line-height 1.6, ≤65ch.
- **OG-«паспорта» 1200×630: satori на сборке** (буфер Rubik, direction rtl; элементы иврита и латиницы разделены). Обязательный визуальный приёмочный тест ивритской карточки. Фоллбек №1 — Playwright-рендер (шрифты из репо); аварийный — cover-фото как og:image автоматически.
- ТЗ съёмки (Gemini) + видео-сценарии: замер → резка → монтаж → уровень → финал.

## 8. Моушн и ассеты
- Параметры: 5–7 структурных слоёв/объект; болты только hero (3–4 шт, 0.3–0.4 с, scale 0.9→1 + пыль); полных сборок на сайт 2–3; ритм секций сборка → прочерчивание → подъём → fade; SplitText-заголовки, stagger 0.08 s, счётчики. Последние 20–25% таймлайна быстрее. Easing power3.out / back.out(1.2). Тень — кроссфейд двух предрендеренных слоёв.
- Техника: вёрстка финального состояния → `gsap.from()`; сборки — scrub 1–1.5; мелочь — once. `ScrollTrigger.normalizeScroll(true)` / `ignoreMobileResize: true`; **запрет 100vh — только 100dvh** в контейнерах анимаций. `gsap.context()` + revert-cleanup. Запрет setTimeout для синхронизации.
- **Z-полосы: слои объектов 10–40, портрет и оверлеи ≥50; Zod-валидация манифеста (zIndex слоя < 50).**
- Деградация-лестница: полный → mobile-вариант манифеста → simplified при `deviceMemory ≤4` или `hardwareConcurrency ≤4` (3 слоя, без пыли) → reduced-motion (мгновенный финал `gsap.set`).
- Слои: **канвас-правило** — каждый слой экспортируется размером ровно финального канваса, прозрачный фон, без кропа; на каждом `<img>` — width/height + `decoding="async"` (hero-слой №1 — `fetchpriority="high"`); бюджет слой ≤120 КБ, объект ≤700 КБ; 1 сборочный объект в вьюпорте.
- Пайплайн: объёмное — Blender (деталь = коллекция/render layer, одна камера, один свет, PNG-альфа); плоское — PSD → PNG; всё через sharp → WebP. **Стартовый ассет-лист:** hero-пергола (Blender, 7 слоёв: столбы, балки ×2, поперечины ×2, ламели, тень + болты 3–4) · забор (PSD, 5–6 слоёв: столбики, лаги, доски ×2, калитка, тень). Артур подтверждает при передаче исходников.
- Правило поддержки: новые анимации собираются из существующих примитивов и таймлайнов, не с нуля.
