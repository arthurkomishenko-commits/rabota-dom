# CLAUDE.md — конвенции проекта Rabota Dom

Рабочий файл для Claude Code. Иерархия документов:

| Документ | О чём | Ранг |
| --- | --- | --- |
| `PROJECT_BRIEF.md` | что решено по продукту | источник правды |
| `CLAUDE_CODE_PROTOCOL.md` | как работать | протокол |
| `docs/ARCHITECTURE_PRINCIPLES.md` | как устроен код: швы, слои, данные | протокол |
| `docs/QUALITY_DOCTRINE.md` | кодекс качества: первопричина, запрет хитростей | протокол |
| `EDITORIAL.md` | тексты | обязателен |
| `docs/PLAN.md` · `docs/manifests/NN-*.md` | фазы и фичи | обязателен |

При конфликте: **бриф** главнее по решениям продукта, **протокол** — по процессу,
**ARCHITECTURE_PRINCIPLES** — по устройству кода, **QUALITY_DOCTRINE** — по тому,
что считается сделанным.

Перед любой работой: прочитать протокол целиком. Без манифеста работу не начинать.
Работа, затрагивающая больше 3 файлов или содержащая больше одного неочевидного
решения, начинается с мини-плана в манифесте (QUALITY_DOCTRINE §3).

## Стек и версии

Astro 7.2 · Tailwind 4.3 (`@tailwindcss/vite`) · TypeScript strict · GSAP (F5) ·
Cloudflare Worker (F4) · Leaflet (F6). Node ≥22.12, в CI — 24.

## Архитектура: швы и слои (ARCHITECTURE_PRINCIPLES)

**Главный закон.** Шов — граница модуля — создаётся при ПЕРВОМ использовании.
Абстракция (обобщение, базовый класс, генерик) — только при ВТОРОМ реальном
использовании. Пустые интерфейсы «на будущее», плагинные системы, state-менеджеры
и обёртки «про запас» запрещены: спекулятивные конструкции превращают проект
в болото быстрее, чем их отсутствие.

Практическое следствие: `lib/money.ts`, `lib/phone.ts`, `lib/analytics.ts`,
`lib/api/` **ещё не существуют** — их пока некому вызывать. Они появятся в фазе
первого реального использования, не раньше.

**Слои и единственно допустимые направления.** Проверяется машинно:

| Слой | Что внутри | Может импортировать |
| --- | --- | --- |
| `src/config/` | весь конфиг одним модулем; магических констант в коде нет | — |
| `src/lib/` | чистые функции без побочных эффектов | config |
| `src/lib/api/` | единственное место сетевых вызовов фронта | config, lib |
| `src/data/` | репозитории данных; единственный, кто знает ОТКУДА данные | config, lib |
| `src/components/` | чистый UI, данные только через props | config, lib |
| `src/layouts/` | каркас документа | config, lib, components |
| `src/pages/` | сборка страницы из data + components, без бизнес-логики | всё выше |
| `worker/` | отдельный сервис, контракт `/api/v1/*` | — |

`import type` через границы разрешён: типы не создают связи во время выполнения,
а контракты живут в `data` (§2). Осознанное отступление — комментарий
`boundary-ok(DEC-XXXX)` в строке **и** запись в DECISIONS.

**Данные на вырост.** Деньги — только целые числа в агоротах, float для денег
запрещён. У работ неизменный `id` и неизменный после публикации `slug`.
`schemaVersion` в каждом JSON-контракте. i18n-ключи по неймспейсам (`nav.*`,
`form.*`, `calc.*`). Даты ISO 8601, телефоны E.164.

**Зарезервировано, занимать нельзя:** `/shop`, `/cart`, `/pay`, `/account`, `/api`.

## Качество (QUALITY_DOCTRINE)

- **Критерий один — качество.** Скорость, стоимость и число итераций не являются
  аргументом ни в одном решении.
- **Правило первопричины.** Сначала диагноз (воспроизведение → причина →
  доказательство причины) в BUGS.md, потом лечение. Магические задержки, подгонка
  значений, подавление ошибок, спецветки «если это тот самый случай» — костыли.
- **Времянка только при внешней блокировке**, с меткой `// TEMP(DEC-XXXX)`
  и записью в DECISIONS. Без ссылки на DEC билд падает.
- **Запрет хитростей.** Ослабить проверку или порог ради прохождения, подавить
  ворнинг, поменять критерий приёмки задним числом, округлить «почти проходит»
  до «проходит» — нарушение протокола. **При провале гейта чинится код, а не гейт.**
- **Полировочный проход** в конце каждой фазы: перечитать весь дифф фазы, прогнать
  все проверки, пройти чек-лист edge-cases (пустые данные · длинные строки · иврит
  и RTL · медленная сеть · без JS · reduced-motion · узкий вьюпорт · клавиатура).
- **Честность.** «Не знаю» — легитимный ответ, за которым сразу следует проверка.
  Плохая новость, доложенная сразу, — норма процесса; скрытая — нарушение.

## Конвенции кода

- **Только логические свойства.** `margin-inline-start`, `inset-inline-end`, `border-block-end`.
  Физические left/right ловит `check:conventions`. Осознанное исключение — комментарий
  `physical-ok` в той же строке.
- **`100vh` запрещён.** Только `100dvh`; утилиты `h-viewport` / `min-h-viewport`.
- **Направления анимаций — параметр, не хардкод.** Для RTL используется `rtlInvertX`,
  а не зеркальная копия таймлайна (бриф §2, §8).
- **Токены только из `docs/DESIGN_TOKENS.md`.** Значения перенесены в
  `src/styles/variables.css` дословно; менять без согласования нельзя (бриф §7).
  Новых цветов «на глаз» не заводить.
- **`site` и `base` живут только в `astro.config.mjs`.** В коде — `Astro.site` и
  `import.meta.env.BASE_URL`. Второй копии адреса быть не должно (DEC-0002).
- **Z-полосы:** слои объектов 10–40, портрет и оверлеи ≥50 (бриф §8). С F2 — Zod-валидация.
- **Изображения:** каждому `<img>` — `width`/`height` и `decoding="async"`;
  первому слою hero — `fetchpriority="high"`.
- **Фильтры на фото — только ниже фолда**, через класс `photo-dim`. В hero и сборках
  `filter` запрещён (бриф §7). Глобального селектора по `img` не заводить.
- `gsap.context()` + revert-cleanup; `setTimeout` для синхронизации запрещён.

## Definition of Done (одного шага)

1. `npm run check` и `npm run build` чисты — без ошибок и ворнингов.
2. Границы слоёв не нарушены; отступлений без записи в DECISIONS нет.
3. Проверено функционально: 3 языка × 2 темы × RTL/LTR.
4. Факт проверки записан в манифест фазы: вывод команды, число или скрин.
   Без факта шаг не считается выполненным (протокол §5, §7, §10).
5. Новое правило проверки считается рабочим только после негативного теста
   в `npm run check:selftest` — зелёная проверка сама по себе не доказывает ничего.
   Результат проверки определяется **кодом возврата**, а не взглядом на
   отфильтрованный вывод: `grep` по логу однажды уже скрыл `- 1 error`
   (BUG-0004). Фильтровать можно только после того, как зафиксирован exit code.
6. Изменения закоммичены осмысленным сообщением, секретов в истории нет.

**Definition of Done фазы** дополнительно включает полировочный проход
(QUALITY_DOCTRINE §4) — он стоит в гейте каждой фазы в `docs/PLAN.md`.

«Готово», «работает», «проверил» без приложенного доказательства — запрещённые слова.

## Тексты

Все тексты — по **EDITORIAL.md**. Иврит финально вычитывает Владимир.
Канонические формулы (траст-формула, ценовая честность, гарантия-заглушка)
берутся из брифа §1 **дословно** и не перефразируются.

Тест перед коммитом: «Владимир сказал бы это вслух клиенту во дворе?»

### BANNED_PHRASES

**Единственный машиночитаемый источник — `scripts/banned-phrases.json`.**
Здесь списка нет намеренно: две копии однажды разойдутся, и разойдутся молча.
EDITORIAL.md описывает правила, JSON хранит сами фразы, `npm run check:phrases`
сканирует записи работ и `src/data/dictionary.ts` и падает при вхождении.

Пополнять список — правкой JSON. Ослаблять его ради прохождения проверки
запрещено (QUALITY_DOCTRINE §2): на переработку возвращается текст.

**Стоп-слова** («качественно», «профессионально», «надёжно», «современно», «лучший») —
не запрещены полностью, но не могут стоять как самостоятельное преимущество: только
рядом с цифрой, материалом или сроком. Проверяется вручную при вычитке.
