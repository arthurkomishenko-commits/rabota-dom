# Отчёт 05 — Worker и формы (F4)

Статус: **код готов и протестирован, гейт ожидает секретов.**
Гейт F4 брифа — «тестовая заявка реально пришла в Telegram, скрин от Артура» —
физически не может быть закрыт без токена бота и аккаунта Cloudflare (Q-01).

## Что сделано

Worker целиком: `POST /api/v1/lead` и `POST /api/v1/review`. Ловушка для ботов,
проверка времени заполнения, ограничение частоты по IP через KV, нормализация
телефона, CORS только своему домену, отправка в Telegram **без `parse_mode`**,
ответ клиенту до завершения отправки.

Фронт форм закончен и работает в мок-режиме: все состояния проверены,
включая 429 и 500.

Двадцать один тест на моках — без сети и без секретов.

## Решения и почему именно так

**Контракт зафиксирован до кода Worker'а.** `src/lib/api/contract.ts` написан
в F3, когда Worker'а ещё не существовало. Благодаря этому F4 реализовывал
готовое соглашение, а фронт удалось закончить, не дожидаясь секретов.

**Копия контракта на стороне Worker'а — осознанная.** Общий модуль связал бы
деплой сайта и деплой Worker'а в одно целое, а контракт нужен ровно для
обратного. Но «независимость» без сверки — это тихий разъезд: однажды на сайте
поменяют маску телефона, Worker останется со старой, и часть заявок начнёт
отбиваться без видимой причины. Поэтому есть тест, читающий **оба** файла
и сравнивающий значения, а не структуру кода.

Этот тест сразу поймал ложное срабатывание на форматировании (`'v1' as const`
против `'v1'`) — сравнение нормализовано: тест, падающий на оформлении,
однажды отключат.

**Без `parse_mode`** — не стилистика. С разметкой Telegram отвечает ошибкой
на любое имя со звёздочкой или подчёркиванием, и заявка теряется молча.
Цена «красивого форматирования» — потерянный клиент. В тестах есть отдельный
случай с именем `Дан*ил`.

**Бот получает такой же ответ, как человек.** Заполненная ловушка или слишком
быстрая отправка приводят к обычной благодарности и ничему больше. Сообщать
боту, что он распознан, значит помогать его отладить.

**Ответ уходит до отправки в Telegram** (`waitUntil`). Человек не должен ждать
чужой API, чтобы увидеть «спасибо».

**Незнакомый источник не получает заголовков CORS вообще** — не «отказ»,
а отсутствие разрешения; браузер сам его отсечёт.

**Скользящее окно вместо календарного часа** для ограничения частоты: ключ
живёт час от первой попытки. Точный алгоритм стоил бы лишней сложности
на ровном месте, а защита от наплыва работает одинаково.

## Что проверено тестами

| Проверка | Почему это дороже всего сломать незаметно |
| --- | --- |
| Сообщение без `parse_mode` | Иначе заявки теряются молча |
| Имя со звёздочкой доходит | Тот же дефект, с конкретным именем |
| Телефон нормализуется | `+972…` и `0…` — один и тот же человек |
| Невалидный телефон отклонён | Иначе мастер получает нерабочий номер |
| Шестая попытка — 429 | Иначе лимит существует только на бумаге |
| Ловушка → тихий успех | Иначе мы отлаживаем чужого бота |
| Отзыв без согласия отклонён | Публикация без согласия — нарушение, а не баг |
| Чужой источник без CORS | Иначе форму дёргают откуда угодно |
| Контракт сайта = контракт Worker | Иначе разъедутся молча |

## Что осталось и от чего зависит

**Только внешнее.** Пошаговая инструкция — `worker/README.md`: бот у @BotFather,
`chat_id`, `wrangler login`, создание KV, два `wrangler secret put`, деплой,
подстановка адреса Worker'а в `API_BASE`.

После деплоя: тестовая заявка → скрин из Telegram → гейт F4 закрыт.

Секретов в репозитории нет и не будет: в коде только имена переменных.
