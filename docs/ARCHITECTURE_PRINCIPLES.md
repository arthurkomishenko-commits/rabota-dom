# ARCHITECTURE_PRINCIPLES.md — Rabota Dom
Размещение: `docs/ARCHITECTURE_PRINCIPLES.md` · Статус: обязателен, ранг = протокол. Бриф главнее по решениям продукта, этот файл — по устройству кода.

## 0. Зачем
Проект будет расти: в будущем возможны оплата (касса), магазин с корзиной, смена хранилища данных. Ничего из этого НЕ строим сейчас. Готовность к росту — это не заранее построенные системы, а **чистые швы**: границы модулей с узкими интерфейсами, через которые любую часть можно заменить, не трогая остальные. Этот документ — закон устройства кода на все фазы.

## 1. Главный закон
- **Шов** (граница модуля) создаётся при ПЕРВОМ использовании — обязателен всегда.
- **Абстракция** (обобщение, базовый класс, генерик) — только при ВТОРОМ реальном использовании.
- Запрещено: пустые интерфейсы «на будущее», плагинные системы, state-менеджеры, БД «про запас», универсальные обёртки. Именно спекулятивные конструкции, а не их отсутствие, превращают проект в болото и вынуждают рефакторинги.

## 2. Карта слоёв и единственно допустимые зависимости
- `src/config/site.ts` — весь конфиг одним модулем: site/base URL, телефон, языки, лимиты, ссылки. Магические константы в коде запрещены.
- `src/data/` — **репозитории данных**: `getWorks()`, `getWork(slug)`, `getMapPoints()`, `getRates()`, `getFaq()`. Единственное место, знающее, откуда данные (astro:content, JSON). Смена хранилища (файлы → D1/Postgres/API) = правка только этого каталога. Схемы: `src/data/schemas/` — одна Zod-схема = один файл + экспорт TS-типа.
- `src/lib/` — чистые функции без побочных эффектов: `money.ts`, `phone.ts`, `url.ts`, i18n-утилиты, анимационные хелперы.
- `src/lib/api/` — **единственное место сетевых вызовов фронта**: `submitLead()`, `submitReview()`. Знает URL Worker, коды ответов, fallback-логику. Компоненты вызывают функции, а не fetch.
- `src/components/` — чистый UI: данные через props; без fetch, без astro:content, без window-глобалей (исключение — выделенные islands).
- `src/pages/` — только сборка страницы из data + components. Бизнес-логики в страницах нет.
- `worker/` — отдельный сервис со стабильным HTTP-контрактом: пути **`/api/v1/*`**; изменение контракта — только новой версией. Фронт и Worker развиваются независимо.
Направление зависимостей: pages → (data | components | lib); components → lib; data → lib. Обратные и циклические импорты запрещены. `lib` не зависит ни от чего.

## 3. Данные на вырост (закладывается с первого коммита)
- **Деньги — только целые числа в минимальных единицах (агороты)** во всех данных и расчётах; float для денег запрещён; форматирование — только `lib/money.ts`. Будущая касса станет добавлением, а не переписыванием расчётов.
- **Стабильные идентификаторы:** у каждой работы `id` (неизменен всегда) и `slug` (после публикации не меняется — это URL, OG-ссылки и будущий ключ БД).
- `schemaVersion` в каждом JSON-контракте (манифесты слоёв, точки карты, rates) — миграции данных скриптуемы.
- i18n-ключи неймспейсами: `nav.*`, `form.*`, `calc.*`, `map.*` — новый раздел сайта = новый неймспейс, а не правка существующих.
- Даты — ISO 8601. Телефоны в данных — E.164, форматирование в `lib/phone.ts`.

## 4. Зарезервировано на будущее (стоит ноль сейчас)
- URL-пространство не занимать ничем: `/shop`, `/cart`, `/pay`, `/account`, `/api`.
- Аналитика: события только через `lib/analytics.ts` по словарю имён (`lead_submit`, `wa_click`, `call_click`, `calc_result`, `map_point_open`…). Воронка магазина позже просто расширит словарь.
- Эволюция платформы, когда понадобятся оплата/магазин: хостинг GitHub Pages → **Cloudflare Pages** (тот же Astro, тот же репозиторий, меняется один workflow) · серверная логика → Functions/Workers рядом с существующим Worker · платежи → внешний провайдер (Stripe / израильские Meshulam, Grow — карты и PCI всегда на стороне провайдера, мы их данные не храним) · заказы → Cloudflare D1 за репозиторием `src/data/`. При соблюдении швов это добавление модулей, не рефакторинг.

## 5. Правила модулей
- Один файл — одна ответственность. Ориентир ≤200 строк (не догма — повод задуматься о разделении).
- Шапка каждого модуля: JSDoc — что делает, вход/выход, кто использует.
- Экспорты именованные; default — только там, где этого требует фреймворк.
- Побочные эффекты — только в `lib/api`, islands и `worker/`.

## 6. Автоматический контроль границ (расширить scripts/check-conventions.mjs)
Билд падает, если:
- `astro:content` импортируется вне `src/data/`;
- `fetch(` встречается вне `src/lib/api/` и `worker/`;
- литералы цен или телефона найдены вне `config`/`data`;
- обнаружен циклический импорт или запрещённое направление между слоями (в меру возможностей статической проверки).
Каждое сознательное отступление — запись в `docs/DECISIONS.md` с причиной и планом возврата.

## 7. Итог
Мы не строим магазин — мы строим сайт, к которому магазин можно привинтить без боли. Разница между этими двумя вещами — швы. Швы обязательны с первого компонента F1.
