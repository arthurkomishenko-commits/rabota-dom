# Манифест 01b — Узаконивание ARCHITECTURE_PRINCIPLES и QUALITY_DOCTRINE

Промежуточный пакет между F0 и F1. Два документа получили ранг протокола уже после
того, как код F0 был написан, — значит код F0 нужно привести в соответствие ДО того,
как на нём начнёт расти дизайн-система. Чинить фундамент дешевле сейчас, чем в F1.

## Цель
Границы слоёв из ARCHITECTURE_PRINCIPLES §2 существуют в коде и проверяются машинно;
метки-костыли из QUALITY_DOCTRINE §8 ловятся в CI; оба документа узаконены в CLAUDE.md;
«полировочный проход» стоит в гейте каждой фазы.

## Связь с документами
ARCHITECTURE_PRINCIPLES §1, §2, §3, §5, §6 · QUALITY_DOCTRINE §3, §4, §8 ·
протокол §3, §5 · бриф §2.

## Мини-план (шаг · способ проверки)

1. **Скрины с телефонов** — просмотреть, зафиксировать что именно доказано,
   закрыть пункт гейта F0. *Проверка:* запись в манифесте 01 с явным перечнем
   подтверждённого и неподтверждённого.
2. **`src/config/site.ts`** — единственный модуль конфига (§2). Внутри: языковая
   матрица, доступ к `site`/`base` через `import.meta.env` (значения по-прежнему
   живут только в `astro.config.mjs` — DEC-0002 не нарушается).
   *Проверка:* `npm run check` зелёный, ни одной магической константы в компонентах.
3. **`src/lib/i18n.ts`** — чистые функции (`stripBase`, `getLocaleFromPath`,
   `getRouteKey`, `isNonLocalizedPath`). `lib` не импортирует ничего, кроме `config`.
   *Проверка:* проверка направления зависимостей в `check-conventions` зелёная.
4. **`src/data/dictionary.ts`** — репозиторий словарей `getDictionary(locale)`,
   ключи по неймспейсам (§3). Компоненты получают строки **через props**, а не
   импортом словаря (§2). *Проверка:* граничная проверка «components не импортируют
   data» проходит; страницы рендерятся на трёх языках.
5. **Расширить `scripts/check-conventions.mjs`** проверками §6: `astro:content` вне
   `src/data/`, `fetch(` вне `src/lib/api/` и `worker/`, литералы цен и телефона вне
   `config`/`data`, направление зависимостей между слоями, занятие зарезервированных
   URL (§4). *Проверка:* негативный тест на каждое правило — нарушение ловится,
   после удаления снова чисто.
6. **`scripts/check-markers.mjs`** — метки TEMP/HACK/FIXME/`@ts-ignore`/
   `@ts-expect-error`/`eslint-disable`/`test.skip` без ссылки на DEC валят билд (§8).
   *Проверка:* негативный тест обоих случаев — со ссылкой на DEC проходит, без — падает.
7. **CLAUDE.md** — оба документа внесены в иерархию и в definition of done;
   карта слоёв и запрет спекулятивных конструкций описаны. *Проверка:* чтение.
8. **`docs/PLAN.md`** — «полировочный проход» добавлен в гейт каждой фазы F0–F9.
   *Проверка:* все девять гейтов содержат пункт.
9. **Полировочный проход по F0** (§4): чек-лист edge-cases на живом сайте —
   без JS, клавиатура, узкий вьюпорт, длинные строки, reduced-motion, RTL.
   *Проверка:* каждая находка в BUGS.md, чинится по правилу первопричины.

## Критерии приёмки
- `npm run check` (конвенции + границы + метки + бюджеты + типы) зелёный.
- Каждое новое правило проверки имеет пройденный негативный тест.
- Ни одного отступления от ARCHITECTURE_PRINCIPLES без записи в DECISIONS.
- Гейт F0 закрыт полностью, включая реальное устройство.
- Полировочный проход F0 выполнен, находки закрыты или зарегистрированы с планом.

## Риски
Перекладывание кода ради «соответствия карте» может само оказаться спекулятивной
работой (§1). Поэтому создаются только те модули, у которых **уже есть** первое
использование: `config/site.ts`, `lib/i18n.ts`, `data/dictionary.ts`.
`lib/money.ts`, `lib/phone.ts`, `lib/analytics.ts`, `lib/api/` **не создаются** —
в F0 их некому вызывать; они появятся в фазе первого реального использования.

## Что нужно от Артура
Ничего. Все входные данные получены.

### Шаги 2–4 — слои появились в коде · ✅ 07.08.2026
Было: `src/i18n/{config,ui}.ts` — конфиг, чистые функции и словари в одной куче,
компоненты импортировали словарь напрямую.
Стало:
```
src/config/site.ts     языковая матрица; SITE_URL и BASE_URL из окружения
src/lib/i18n.ts        stripBase · getLocaleFromPath · getRouteKey · isNonLocalizedPath
src/data/dictionary.ts getDictionary(locale), ключи по неймспейсам (theme.*, scaffold.*)
```
Страницы получают словарь и передают строки в компоненты **через props** —
`FoundationCheck` больше не знает, откуда берутся тексты.
DEC-0002 не нарушен: значения `site`/`base` остались только в `astro.config.mjs`,
`config/site.ts` их читает из `import.meta.env`, а не дублирует.
Сознательно **не созданы** `lib/money.ts`, `lib/phone.ts`, `lib/analytics.ts`,
`lib/api/` — в F0 их некому вызывать, это был бы ровно тот спекулятивный код,
который запрещает §1.
Факт: `npx astro check` → 0 errors, 0 warnings, 0 hints (18 файлов); билд 4 страницы.

### Шаг 5 — границы проверяются машинно · ✅ 07.08.2026

### Самотест проверок · ✅ 07.08.2026

«осознанное исключение пропускается» и «после уборки снова чисто».

```
✓ vh · физическое свойство · text-align · смещение · float
✓ astro:content вне data · fetch вне api · литерал телефона · литерал цены
```

поэтому заведён явный закрытый список файлов-исключений. Разобрано в BUGS.md.
