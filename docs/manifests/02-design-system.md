# Манифест 02 — Дизайн-система (F1)

## Цель
Набор компонентов, из которых дальше собираются все страницы: кнопка, инпут,
тег материала, карточка-«паспорт объекта», sticky-панель трёх каналов, диммер фото.
Каждый компонент — с чистым швом: данные через props, ноль знаний о том, откуда
они пришли. Ни одной страницы в этой фазе не верстается.

## Связь с документами
Бриф §7 (токены, кнопка, инпуты, тег, фокус-кольца, диммер), §3 (sticky-панель
трёх каналов), §4 (карточка-паспорт: рамка 1px, фото 4:3 со «спилом» clip-path,
зеркалится в RTL, штамп monospace, метрики) · `docs/DESIGN_TOKENS.md` ·
ARCHITECTURE_PRINCIPLES §1, §2, §5 · QUALITY_DOCTRINE §3, §4 · протокол §5, §7.

## Что нужно от Артура (до старта)
1. **Ничего блокирующего.** Токены получены, доктрины узаконены.
2. К шагу 4 понадобится **одно тестовое фото 4:3** любого объекта — чтобы «спил»
   clip-path и диммер проверялись на реальном кадре, а не на сером прямоугольнике.
   ЗАЧЕМ: форма спила читается только на фотографии с содержанием.
   КАК: любой снимок из архива, JPEG, длинная сторона ≥1600px, в `docs/evidence/f1/`.
   Пока фото нет — шаг 4 идёт на плейсхолдере и помечается как неполный.

## Мини-план (QUALITY_DOCTRINE §3)

Каждый шаг: сборка компонента → доказательство (скрины всех состояний ×2 темы
×2 направления + цифры контраста) → запись факта сюда → следующий шаг.

1. **Витрина компонентов** — страница `/__ui/` (закрыта `noindex`, удаляется в F8).
   Единственное место, где компоненты показываются во всех состояниях сразу;
   на неё же нацелен скриншот-прогон. *Проверка:* страница собирается, в навигацию
   не входит, `check:conventions` зелёный.
2. **Кнопка «матовый алюминий»** — 5 состояний из `DESIGN_TOKENS.md` дословно
   (normal, hover, active, focus, disabled), обе темы. Варианты: primary и
   вторичная текстовая ссылка (бриф §3: иерархия CTA).
   *Проверка:* скрины 5 состояний ×2 темы; `disabled` не фокусируется с клавиатуры;
   фокус-кольцо видно в обеих темах.
3. **Инпут** — нижняя «линия чертежа» становится активной на focus, плейсхолдер
   токеном `--text-muted`, состояние ошибки. *Проверка:* скрины; ввод иврита
   выравнивается по RTL, номер телефона внутри ивритской формы — `dir="ltr"`.
4. **Тег материала** и **карточка-«паспорт объекта»** — рамка 1px, фото 4:3 со
   «спилом» clip-path, **зеркалится в RTL**, штамп monospace (название · город ·
   год) и метрики. Метрика без данных не рендерится вообще (бриф §4: фейки
   запрещены). *Проверка:* скрины he/ru/en ×2 темы; карточка с неполными данными
   не показывает пустых мест.
5. **Sticky-панель трёх каналов** (бриф §3) — WhatsApp · Позвонить · Заявка,
   равноправные, появляется со второго экрана, hero не перекрывает.
   *Проверка:* на 320px три цели не «слипаются», каждая ≥44px по короткой стороне;
   панель не накрывает контент внизу страницы.
6. **Диммер фото** `photo-dim` — довести до финального вида (DEC-0005).
   *Проверка:* применяется только к помеченным фото; в hero-контейнере `filter`
   отсутствует — проверяется вычисленным стилем, а не глазами.
7. **Контраст AA** — измерить пары токенов инструментом, приложить цифры.
   *Проверка:* отчёт с числами по каждой паре; `--accent-wood` на мелком тексте
   не используется (в `DESIGN_TOKENS.md` он помечен как «на грани AA для small text»).
8. **Полировочный проход F1** (QUALITY_DOCTRINE §4) — расширить `polish-pass.mjs`
   витриной компонентов: клавиатура по всем интерактивам, 320px, длинные строки
   в карточке, reduced-motion, без JS.

## Критерии приёмки

Общие для фазы:
- Скрины **всех** состояний **всех** компонентов: 2 темы × 2 направления.
- Контраст AA подтверждён **цифрами**, а не утверждением.
- `npm run check` и `npm run polish` зелёные.
- Полировочный проход выполнен, находки закрыты или зарегистрированы с планом.

Для **каждого** компонента отдельно:
- **ARCHITECTURE_PRINCIPLES §2:** данные только через props; ни `fetch`, ни
  `astro:content`, ни обращений к `window` вне выделенных islands; направление
  зависимостей не нарушено (`check:conventions` зелёный).
- **ARCHITECTURE_PRINCIPLES §5:** одна ответственность на файл, ориентир ≤200 строк;
  шапка-JSDoc «что делает · вход/выход · кто использует»; экспорты именованные.
- **§1:** второй похожий компонент не обобщается в общий базовый — обобщение
  только при втором **реальном** использовании, и это отдельное решение.
- **QUALITY_DOCTRINE §4:** компонент прошёл чек-лист edge-cases — пустые и
  минимальные данные · очень длинные строки · иврит и RTL · без JS ·
  reduced-motion · 320px · клавиатурная навигация.

## Риски
- **Обобщение раньше времени.** Кнопка и sticky-панель внешне похожи — соблазн
  сразу завести «базовый интерактив». §1 это запрещает: сначала два реальных
  использования, потом абстракция.
- **Карточка-паспорт — самый тяжёлый компонент фазы** (clip-path + RTL-зеркало +
  условные метрики). Делается последней из статических, на реальном фото.
- **Контраст `--accent-wood`.** Источник токенов сам предупреждает, что светлый
  вариант на белом на грани AA для мелкого текста. Если измерение это подтвердит —
  это не повод менять токен молча: вопрос к Артуру, решение в DECISIONS.

## Что НЕ входит в F1
Анимации (F5 — стилистику заранее не решаем, режиссура идёт через внешний контур,
протокол §11), реальные тексты (F3, после EDITORIAL и вычитки), данные работ
(F2), формы с отправкой (F4).
