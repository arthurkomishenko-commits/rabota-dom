# Манифест 06 — Анимационная система (F5)

## Цель
Система, а не набор эффектов: примитивы, загрузчик манифестов слоёв,
деградация-лестница и ритм секций. Hero-сборка собирается из этих примитивов
и помечается **черновой** до ответов внешнего раунда (протокол §14.3).

## Связь с документами
Бриф §8 (параметры и техника), §3 (покадровая режиссура первого экрана),
§7 (запрет фильтров в hero) · протокол §8 · схема манифеста слоёв из F2
(`src/data/schemas/layer-manifest.ts`, уже готова) · `docs/external/01-hero-choreography.md`.

## Что нужно от Артура
- Исходники Blender и PSD по ассет-листу брифа §8 (Q-03).
- Результаты внешнего раунда по режиссуре (`docs/external/01-...`).

До получения — работа не останавливается: слои заменяются схематичными,
нарисованными нами; манифест описывает слои **данными**, поэтому подмена
исходников не потребует переписывания режиссуры.

## Мини-план

1. **Загрузчик манифеста слоёв.** Читает описание объекта, проверяет схемой
   (готова в F2), отдаёт слои компоненту. *Проверка:* манифест со слоем
   `zIndex: 50` валит билд; ссылка на несуществующий слой в варианте
   деградации валит билд.

2. **`LayeredObject`** — рендер слоёв по манифесту. Каждый `<img>` получает
   `width`/`height` и `decoding="async"`, первый слой hero — `fetchpriority="high"`.
   Канвас-правило: слой равен размеру финального кадра, без кропа.
   *Проверка:* CLS остаётся 0.000 на странице со сборкой.

3. **Примитивы движения:** `ScrollReveal`, прочерчивание линий, счётчики,
   заголовки по словам. Все — на `gsap.context()` с revert-очисткой.
   `setTimeout` для синхронизации запрещён. *Проверка:* уход со страницы
   не оставляет живых таймлайнов (счётчик активных твинов после cleanup — ноль).

4. **Деградация-лестница.** Полный вариант → мобильный вариант манифеста →
   упрощённый (`deviceMemory ≤ 4` или `hardwareConcurrency ≤ 4`: три слоя,
   без пыли) → `prefers-reduced-motion`: мгновенный финал через `gsap.set`.
   *Проверка:* каждая ступень проверяется отдельно, подменой условий;
   при reduced-motion финальный кадр виден сразу, без промежуточных состояний.

5. **Hero-сборка v1** строго по режиссуре брифа §3: покадровые отрезки 0–1,
   1–3, 3–5 с, стоп на 85–90%, болты 3–4 штуки. Помечается черновой.
   *Проверка:* тайминги снимаются кадрами, а не на глаз; 60 fps при
   троттлинге CPU ×4.

6. **RTL как параметр.** Горизонтальные направления зеркалятся через
   `rtlInvertX`, вертикальные — нет. Зеркальной копии таймлайна не заводится.
   *Проверка:* один и тот же таймлайн даёт зеркальное движение в RTL.

7. **Ритм секций** ниже первого экрана: сборка → прочерчивание → подъём →
   затухание. *Проверка:* тест-грань «круто собралось», а не «много летало» —
   формулируется как отчёт с кадрами, решение принимает Артур.

8. **Полировочный проход F5** плюс отдельная проверка: 60 fps при CPU ×4
   на каждой сборке.

## Критерии приёмки
- 60 fps при троттлинге CPU ×4 на всех сборках — цифры приложены.
- `prefers-reduced-motion` показывает финал мгновенно.
- RTL-направления зеркалятся, зеркальных копий таймлайнов нет.
- Уход со страницы не оставляет активных твинов.
- CLS не вырос: сборка не двигает раскладку.
- Hero помечен черновым до ответов внешнего раунда.

## Риски
- **Соблазн упростить «потому что сложно»** — прямой запрет протокола §10:
  сложность здесь заложена намеренно.
- **Анимация ради анимации.** Приёмочная грань — «круто собралось».
  Если экран не отвечает на свой вопрос быстрее без движения, движение лишнее.
- **Схематичные слои вместо настоящих.** Черновая сборка на наших схемах
  может выглядеть убедительнее, чем окажется на реальных слоях. Поэтому
  hero помечается черновой явно, а не «почти готовой».

## Что НЕ входит
Карта (F6), калькулятор (F7), OG и SEO (F8).
