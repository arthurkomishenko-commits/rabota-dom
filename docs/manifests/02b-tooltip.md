# Манифест 02b — Тултип и доступные имена (Норма А)

Дополнение к дизайн-системе F1. Основание: бриф §14 (ревизия v2.1), DEC-0015.

## Цель
Ни один интерактив без видимого текста не остаётся безымянным, а подсказка
одинаково доступна мышью, клавиатурой и пальцем.

## Что нужно от Артура
Ничего. Требование сформулировано полностью.

## Мини-план

1. **Доступные имена — машинно.** Пропсы компонентов, у которых нет видимого
   текста (иконка-кнопка, тумблер темы, кнопка панели доступности), делают
   `ariaLabel` **обязательным** на уровне типа: забыть его нельзя, сборка не
   пройдёт. *Проверка:* попытка отрендерить такой компонент без имени валит
   `astro check`; негативный тест в самотесте.
2. **Аудит живого DOM** в полировочном проходе: каждый интерактив имеет
   непустое доступное имя. *Проверка:* правило в `polish-pass.mjs`, которое
   перечисляет нарушителей поимённо, а не считает их количество.
3. **Примитив `Tooltip`.** Показ на `mouseenter` **и** на `focus-visible`,
   задержка ~300 мс, закрытие по Esc и по уходу фокуса, подсказка не
   перекрывает собственную цель, позиционирование логическое (RTL-aware).
   *Проверка:* клавиатурный сценарий в полировке — Tab до цели, подсказка
   появилась, Esc закрыл, фокус остался на цели.
4. **Семантика без двойной озвучки.** По WAI-ARIA Authoring Practices:
   если у цели нет своего имени — тултип становится именем (`aria-labelledby`);
   если имя уже есть — тултип становится описанием (`aria-describedby`).
   Одновременно и то и другое запрещено. *Проверка:* тест доступного имени
   и описания на обоих случаях; кнопке с видимым текстом дубль-тултип не ставится
   (правило в `check-conventions`).
5. **WCAG 1.4.13** — hoverable (курсор можно перевести на саму подсказку),
   dismissible (Esc), persistent (не исчезает сама по таймеру).
   *Проверка:* три отдельных сценария в полировке, по одному на свойство.
6. **Тач.** Критичная информация не живёт только в тултипе: на узком вьюпорте
   она либо видима текстом, либо очевидна из контекста.
   *Проверка:* полировка на 320px — сценарий, где подсказка недоступна,
   не должен оставлять пользователя без информации.

## Критерии приёмки
- Компонент без видимого текста невозможно собрать без доступного имени.
- Аудит живого DOM: нарушителей ноль, список пуст в выводе полировки.
- Клавиатура, Esc, hoverable, persistent — по отдельному пройденному сценарию.
- Ни одного случая двойной озвучки (имя + описание одним и тем же текстом).

## Риски
- **Тултип как способ спрятать текст.** Соблазн убрать поясняющую строку
  в подсказку ради чистоты макета. Это ухудшение доступности, а не улучшение
  дизайна: критичное остаётся видимым.
- **Задержка 300 мс против клавиатуры.** На фокус подсказка должна появляться
  без задержки — задержка нужна только против случайного пролёта курсором.
