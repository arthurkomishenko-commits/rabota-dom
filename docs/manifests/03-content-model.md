# Манифест 03 — Контент-модель (F2)

## Цель
Данные работ становятся типизированными и проверяемыми: невалидная запись валит
билд, неполный объект не публикуется. Ни одной новой страницы в фазе не верстается —
только модель, репозиторий и проверки. Карточка из F1 начинает получать
настоящие данные вместо демонстрационных props.

## Связь с документами
Бриф §4 (контент-пакет, метрики, фейки запрещены), §5 (coords), §8 (манифест слоёв,
`zIndex < 50`), §10 (CI-гейты) · ARCHITECTURE_PRINCIPLES §2 (data — единственный,
кто знает, откуда данные), §3 (стабильные `id`/`slug`, `schemaVersion`, ISO-даты,
деньги целыми агоротами), §1 (шов при первом использовании) · QUALITY_DOCTRINE §3, §4 ·
EDITORIAL.md · `docs/INTAKE_TEMPLATE.md` · DEC-0013.

## Что нужно от Артура
1. **2–3 реальных паспорта** по `docs/INTAKE_TEMPLATE.md` в `content/works/work-NN/`
   (DEC-0013). Достаточно для разработки и проверки гейта; полные ≥8 — гейт запуска
   в F8, не блокер этой фазы.
2. До их появления работа идёт на **явно помеченной непубликуемой фикстуре**
   (разрешено Артуром 08.08.2026). Фикстура удаляется вместе с появлением
   второго реального паспорта.

## Мини-план (QUALITY_DOCTRINE §3)

Каждый шаг: изменение → доказательство (вывод команды с кодом возврата, число,
снимок) → запись факта сюда → следующий шаг. Новое правило проверки не считается
рабочим без негативного теста в `npm run check:selftest`.

1. **Коллекция и её конфиг.** `src/content.config.ts`: коллекция `works`,
   loader `glob({ base: './content/works', pattern: '**/{he,ru,en}.mdx' })`.
   `intake.md` и `photos/` под шаблон не попадают и в сборку не идут.
   *Проверка:* пустая коллекция собирается, `astro check` 0/0/0,
   `intake.md` отсутствует в `dist/` (`check:surface`).

2. **Схема работы** — `src/data/schemas/work.ts`, одна схема = один файл + экспорт
   TS-типа (§2). Обязательный минимум = контент-пакет брифа §4: cover · ≥3 фото,
   из них ≥1 процесс или до/после · тип · материал · город · год · срок · описание
   ≥2 предложений · ≥1 метрика · огрублённые coords. Плюс §3 принципов: неизменный
   `id`, `slug` (после публикации не меняется), `schemaVersion`, даты ISO 8601.
   *Проверка:* запись без cover / с двумя фото / без метрик **валит билд** —
   негативный тест на каждое обязательное поле.

3. **Типизированные технические значения + рендер-хелпер** (перенос из BUG-0005).
   Размеры `4×3`, профили `100×50`, диапазоны, крепёж `M12` перестают быть
   свободными строками и получают тип в схеме. Появляется единый хелпер рендера
   с `bdi dir="ltr"` — это его **первое реальное использование**, законный момент
   по §1. `WorkCard.astro` переводится на хелпер, ручная обёртка из F1 снимается.
   Правило «`bdi` только внутри хелпера» добавляется в `check-conventions`.
   *Проверка:* негативный тест правила в самотесте; **визуальное** доказательство —
   снимок RTL-карточки, не `textContent` (QUALITY_DOCTRINE §6).

4. **Схема манифеста слоёв** — `zIndex < 50` (бриф §8, протокол §8), варианты
   mobile и reduced. Пока без анимаций: в F5 система приходит на готовый контракт.
   *Проверка:* манифест со слоем `zIndex: 50` валит билд.

5. **Репозиторий данных** — `src/data/works.ts`: `getWorks(locale)`, `getWork(slug)`.
   Единственное место, знающее про `astro:content` (§2, проверяется машинно).
   *Проверка:* компонент получает данные через props страницы; `check:conventions`
   зелёный; смена источника данных потребует правки только этого файла.

6. **CI banned-phrases** по EDITORIAL.md: сканирует MDX работ и
   `src/data/dictionary.ts`. *Проверка:* негативный тест — запись с фразой
   из списка валит билд; фраза в комментарии-описании правила не ловится
   (урок BUG-0004: проверка не должна ругаться на текст о себе).

7. **Бюджеты оригиналов** — `content/works/**/photos/*` в `check:budgets`:
   1600–2400px по длинной стороне, ≤1.5 МБ (DEC-0013).
   *Проверка:* негативный тест на превышение и на недобор размера.

8. **Фикстуры схемы** — явно помеченные и непубликуемые. Правило в
   `check:surface`: помеченная фикстура в `dist/` валит сборку.
   *Проверка:* негативный тест; фикстура удаляется при появлении второго
   реального паспорта.

9. **Первые реальные записи** — 2–3 паспорта превращаются в записи he/ru/en,
   рендерятся карточкой из F1. Тексты проходят EDITORIAL; иврит помечается
   как ожидающий вычитки Владимиром.
   *Проверка:* снимки карточек с реальными данными, 3 языка × 2 темы.

10. **Полировочный проход F2** (QUALITY_DOCTRINE §4): чек-лист edge-cases на
    записях — работа с минимумом полей · очень длинные названия · иврит и RTL ·
    отсутствующие метрики · отсутствующий отзыв · 320px · без JS.

## Критерии приёмки

Гейт фазы (docs/PLAN.md → F2):
- Невалидная запись **валит билд** — показано негативным тестом на каждое
  обязательное поле, а не одним общим.
- Тестовая запись рендерится на трёх языках — снимки приложены.
- Полировочный проход выполнен, находки закрыты или зарегистрированы с планом.

Дополнительно, по документам ранга протокола:
- **§2:** `astro:content` встречается только в `src/data/` — проверяется машинно.
  Компоненты по-прежнему получают данные через props.
- **§3:** у каждой работы неизменный `id` и `slug`; в каждом JSON-контракте
  `schemaVersion`; даты ISO 8601; технические значения типизированы.
- **§1:** хелпер рендера появляется на первом реальном использовании; второй
  похожий на `WorkCard` компонент не обобщается «на будущее».
- **§6 доктрины:** каждое утверждение подтверждено доказательством, которое
  измеряет именно утверждаемое; результат проверки — по коду возврата.

## Риски
- **Схема, написанная под фикстуру, а не под жизнь.** Реальные паспорта почти
  наверняка принесут поля, которых нет в шаблоне (или пустые там, где ожидалась
  обязательность). Поэтому схема фиксируется **после** первых реальных паспортов,
  а не до: шаги 1–4 делаются на фикстуре, шаг 9 имеет право вернуть нас к шагу 2.
- **Соблазн ослабить обязательность**, когда реальный паспорт не пройдёт гейт.
  Это прямой запрет QUALITY_DOCTRINE §2: чинится содержимое паспорта или,
  если требование объективно завышено, — отдельное решение через Артура ДО правки.
- **Пайплайн изображений не выбран** (открытая запись в DECISIONS). Шаги 1–8
  от него не зависят; шаг 9 упрётся — решение принимается там, с реальными фото
  на руках, а не гаданием.

## Что НЕ входит в F2
Страницы портфолио и фильтры (F3), Worker и формы (F4), анимации (F5),
карта (F6), калькулятор и ставки (F7).

## Требование, перенесённое из F1: типизированные технические значения

**Источник — BUG-0005.** В RTL метрика `100×50` отображалась как `50×100`:
символ `×` нейтральный, алгоритм bidi разрешает его в направление абзаца
и переставляет числовые прогоны. Значение меняло **смысл**, а не только вид.

В F1 это вылечено точечно — `<bdi dir="ltr">` в `WorkCard.astro`. Точечное
лечение не масштабируется: тот же дефект ждёт размеры `4×3`, диапазоны
`2–3 дня`, профили, крепёж `M12`, координаты, площади, погонные метры.

Решение Артура от 08.08.2026 — шаг 3 мини-плана выше:
типизировать поля в схеме · единый рендер-хелпер с `bdi dir="ltr"` ·
после появления хелпера ручные обёртки по месту **запрещены**.

## Факты выполнения


### Шаги 1–8 · ✅ 09.08.2026 (на фикстуре, как разрешил Артур)

**Шаг 1 — коллекция.** `src/content.config.ts`: `glob({ base: './content/works',
pattern: '**/{he,ru,en}.mdx' })`. `intake.md` и `photos/` под шаблон не подходят
и в сборку не идут. Подключён `@astrojs/mdx`.
Граница: Astro требует конфиг строго в `src/content.config.ts`, поэтому файл
физически вне `src/data/`. По смыслу это объявление источника данных — проверка
границ трактует его как слой `data` (явное правило в `check-conventions`,
а не молчаливое исключение).

**Шаг 2 — схема работы** (`src/data/schemas/work.ts`). Обязательный минимум
брифа §4 плюс §3 принципов: `schemaVersion`, неизменный `id`, `slug`, ISO-даты.
Ни одного поля «на всякий случай» со значением по умолчанию: пустая строка не
проходит, чтобы у автора записи не осталось способа «заполнить, чтобы прошло».

Заложена **проверка приватности, которой не было в плане**: координаты обязаны
быть огрублены (бриф §5). Больше трёх знаков после запятой — это точный адрес
клиента, и билд падает. Факт, негативный тест:
```
coords.lat: координата не огрублена: оставьте не больше трёх знаков после
запятой (~110 м). Точный адрес клиента в репозиторий не кладётся (бриф §5)
```

**Шаг 3 — типизированные технические значения и единый рендер.**
`src/data/schemas/technical.ts` — размеры, габариты, диапазоны, обозначения, год
как структуры. `src/lib/technical.ts` — чистое форматирование, подписи единиц
приходят параметром (lib не знает языка). `src/components/TechnicalValue.astro` —
**единственное место с `<bdi>`**.
`WorkCard` переведён на хелпер, ручная обёртка из F1 снята.
Правило «`bdi` только у владельца» — в `check-conventions`, негативный тест
в самотесте (`manual-bdi.astro → ловится`).
Визуальное доказательство (не `textContent`, урок BUG-0005): `card-rtl.png` —
в RTL метрика читается «100×50 мм», порядок сохранён.

**Шаг 4 — манифест слоёв** (`src/data/schemas/layer-manifest.ts`): 3–7 слоёв,
`zIndex` 10–49, обязательные width/height (канвас-правило), варианты mobile
и simplified обязаны ссылаться на существующие слои. F5 придёт на готовый
контракт, а не будет изобретать его вместе с анимацией.

**Шаг 5 — репозиторий** `src/data/works.ts`: `getWorks(locale)`, `getWork(...)`.
Единственное место, знающее про `astro:content` (проверяется машинно).
Фикстуры отсекаются здесь, а не в вызывающем коде, — забыть про фильтр негде.

**Шаг 6 — запрещённые фразы.** `scripts/check-phrases.mjs` сканирует записи работ
и `src/data/dictionary.ts`. Список вынесен в `scripts/banned-phrases.json` —
**единственный** машиночитаемый источник; вторая копия из `CLAUDE.md` удалена,
там теперь ссылка. Две копии списка однажды разошлись бы молча.
Негативный тест: фраза в записи работы ловится.

**Шаг 7 — бюджеты оригиналов.** `check:budgets` читает размеры из заголовка
файла (JPEG/PNG/WebP, без зависимостей) и требует 1600–2400px и ≤1.5 МБ
(DEC-0013). Негативный тест: файл 1×1 ловится по нижней границе.

**Шаг 8 — фикстуры.** `check:surface` собирает слаги записей с `fixture: true`
и падает, если такая страница попала в `dist/`. Проверяется факт, а не намерение:
если фильтр в репозитории однажды снимут, поймает эта проверка.

### Побочная находка: `z` из `astro:content` устарел

`astro check` выдавал 65 подсказок ts(6385): в Astro 7 внутри используется
`zod/v4`, и старый реэкспорт `z` помечен устаревшим, как и `_output`.
Глушить подсказки не стал — перевёл схемы на прямой импорт `zod` (добавлен
явной зависимостью, версия совпадает с той, что тянет Astro) и вернул `z.infer`
вместо `_output`, `z.iso.date()` вместо устаревшего `z.string().date()`.

Проверено главное — что Astro по-прежнему валидирует контент схемой из другого
модуля: валидная запись собирается, невалидная валит билд с сообщением из схемы.
Итог: `astro check` → 0 errors, 0 warnings, **0 hints**.

### Две находки шага 9 — обе из тех, что план предсказывал

**BUG-0006 — две локали из трёх молча пропадали.** Loader брал `id` из поля
`slug`, а он у трёх языков общий. Записи схлопывались; сборка зелёная, карточек
нет. Схема поймать не могла — каждая запись по отдельности валидна. Починено
`generateId` из пути файла; заведена проверка `check:content`, которой не было.

**BUG-0007 — не было поля `title`, материал утекал кодом.** Схема писалась под
фикстуру: «рабочее название» есть в шаблоне паспорта, но в схеме его не было,
и карточка резала описание по первой точке; материал показывался как `WOOD`.
Добавлено поле `title` и неймспейс `materials` в словарь.

Обе поймал снимок, а не проверка. Это ровно риск «схема под фикстуру, а не под
жизнь», записанный в этом же манифесте, — и сработал он на демо, то есть дёшево.
