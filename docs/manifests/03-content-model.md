## Требование, перенесённое из F1: типизированные технические значения

**Источник — BUG-0005.** В RTL метрика `100×50` отображалась как `50×100`:
символ `×` нейтральный, алгоритм bidi разрешает его в направление абзаца и
переставляет числовые прогоны. Значение меняло **смысл**, а не только вид.

В F1 это вылечено точечно — `<bdi dir="ltr">` в `WorkCard.astro`. Точечное
лечение не масштабируется: тот же дефект ждёт любые технические значения —
размеры `4×3`, диапазоны `2–3 дня`, профили `100×50`, крепёж `M12`, координаты,
версии, площади, погонные метры.

### Что делать в F2 (решение Артура от 08.08.2026)

1. **Типизировать поля в схемах, а не хранить их строками.** Размеры, модели,
   диапазоны и единицы получают собственные типы в `src/data/schemas/`, чтобы
   «100×50» перестало быть свободной строкой и стало значением известной формы.
2. **Единый рендер-хелпер** для таких значений — с `bdi dir="ltr"` внутри.
   Это и есть его **первое реальное использование**, то есть законный момент
   для появления по ARCHITECTURE_PRINCIPLES §1: раньше повода не было,
   в F1 хватало одного места.
3. **После появления хелпера ручные обёртки по месту запрещены.**
   `WorkCard.astro` переводится на хелпер в этой же фазе — точечная обёртка,
   поставленная в F1, снимается.

### Как это будет проверяться
- Схема отвергает техническое значение, записанное свободной строкой.
- Проверка конвенций ловит `bdi` вне хелпера (правило добавляется
  в `scripts/check-conventions.mjs` вместе с хелпером, с негативным тестом
  в `npm run check:selftest` — иначе правило не считается рабочим).
- Визуальное доказательство — снимок RTL-карточки, а не `textContent`
  (QUALITY_DOCTRINE §6: доказательство измеряет то, что утверждается).
