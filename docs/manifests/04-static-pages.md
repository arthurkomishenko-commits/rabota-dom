# Манифест 04 — Статические страницы (F3)

## Цель
Сайт становится сайтом: появляются все страницы из брифа §3 на трёх языках,
собранные из компонентов F1 и данных F2. Анимаций нет — hero статичный
плейсхолдер, «живой чертёж» в статичной версии. Формы стоят, но не отправляют
(Worker в F4) — вместо отправки работает WhatsApp-ветка.

## Связь с документами
Бриф §1 (тексты и канонические формулы), §3 (структура и 10 экранов главной),
§4 (портфолио, паспорта, живой чертёж), §5 (тизер карты), §7 (типографика),
§10 (LHCI, доступность) · EDITORIAL.md · ARCHITECTURE_PRINCIPLES §2, §5 ·
QUALITY_DOCTRINE §3, §4 · манифесты 02b (Норма А) и 05 (Норма Б).

## Что нужно от Артура
Ничего блокирующего. Режим марафона (протокол §14): обратимое решаю сам
с пометкой [AUTO], необратимое уходит в `docs/QUESTIONS_FOR_ARTUR.md`.
Вычитка текстов мастером входит в Content Freeze, а не в эту фазу (DEC-0018).

## Мини-план (QUALITY_DOCTRINE §3)

Каждый шаг: изменение → доказательство с кодом возврата или снимком →
факт сюда → следующий. Новое правило проверки — только с негативным тестом.

1. **Маршрутная сетка и словарь страниц.** Все страницы заводятся сразу на трёх
   языках через один генератор путей; `src/config/site.ts` получает карту
   маршрутов, `src/data/dictionary.ts` — неймспейсы `nav.*`, `home.*`, `services.*`,
   `forms.*`, `legal.*`. *Проверка:* `check:content`-класс для словарей —
   у всех локалей одинаковый набор ключей, иначе билд падает (кодекс §6).
2. **Каркас страницы:** шапка с логотипом и переключателем языка, подвал,
   `PageLayout` поверх `BaseLayout`. *Проверка:* hreflang и canonical на каждой
   новой странице; скелет проходит `check:surface`.
3. **Юридические страницы** `/privacy` (включая политику удаления отзывов ≤7 дней)
   и `/accessibility` (הצהרת נגישות). Делаются первыми: они не зависят ни от чего
   и снимают риск «допишем перед запуском». *Проверка:* тексты по EDITORIAL §10,
   без канцелярита; `check:phrases` зелёный.
4. **404 трёхъязычная** с детектом языка. *Проверка:* страница собирается,
   не попадает в sitemap, не ломает `check:surface`.
5. **Норма А — тултип и доступные имена** (манифест 02b целиком).
6. **Портфолио:** `/portfolio` со списком карточек, фильтры (тип · материал ·
   город · до-после), `/portfolio/[slug]` — паспорт объекта, лайтбокс,
   «живой чертёж» в статичной версии. *Проверка:* фильтры работают без JS
   (ссылки, а не только скрипт); лайтбокс закрывается Esc и возвращает фокус.
7. **Услуги:** `/services` + `/pergolas` `/canopies` `/fences`.
   Анти-шаблонные блоки рендерятся **только при наличии ассета**, иначе блок
   скрыт целиком (бриф §4). *Проверка:* блок без ассета не оставляет пустого места.
8. **Главная — 10 экранов** по брифу §3, каждый отвечает на один вопрос.
   Hero статичный. Блок «последние проекты» показывается при ≥3 полных паспортах,
   тизер карты — при ≥6 точках, иначе скрыт. *Проверка:* поведение гейтов
   проверяется на текущем контенте (2 демо-работы → блоки скрыты).
9. **Формы без отправки:** мини-форма и полная, состояния, экран благодарности,
   постоянная кнопка WhatsApp. Отправка — через `src/lib/api/` в мок-режиме,
   реальный Worker в F4. *Проверка:* мок-режим показывает все состояния,
   включая 429 и 500.
10. **Sticky-панель** подключается к реальному hero: появляется со второго экрана.
11. **Норма Б — панель доступности** (манифест 05 целиком).
12. **LHCI на PR**: mobile ≥90 все категории, бюджеты брифа §10.
    *Проверка:* прогон на всех страницах, четыре цифры приложены.
13. **Полировочный проход F3** — чек-лист на **каждой** странице, включая все
    режимы панели доступности.

## Критерии приёмки
- Все страницы брифа §3 существуют на трёх языках, hreflang корректен.
- LHCI mobile ≥90 на всех страницах — цифры приложены.
- Тексты прошли EDITORIAL и `check:phrases`; канонические формулы — дословно.
- Клавиатура: каждая страница проходима без мыши; фокус виден везде.
- Норма А и Норма Б закрыты по своим манифестам.
- Полировочный проход выполнен, находки закрыты.

## Риски
- **Объём.** F3 — самая большая фаза. Дробится по страницам; каждая страница
  закрывается полностью (текст + доступность + RTL), а не «сначала все каркасы».
- **Тексты.** Соблазн написать рекламное. Правила EDITORIAL применяются к
  каждому абзацу, тест «сказал бы это Владимир вслух» — обязателен.
- **Пустые блоки.** Контента мало (2 демо-работы). Блок без данных обязан
  исчезать целиком, а не показывать заглушку — иначе сайт выглядит недоделанным
  именно там, где должен выглядеть спокойным.

## Факты выполнения


### Шаги 1–4 · ✅ 10.08.2026

**Шаг 1 — маршрутная сетка и словари.** `ROUTES` и `NAV_ORDER` в `src/config/site.ts`:
один источник адресов, навигация строится из него. `NAV_ORDER` отделён от карты
маршрутов намеренно — калькулятор и карта существуют, но в меню не показываются,
пока ставки в draft и точек меньше шести (бриф §5, §6).
Словарь получил неймспейсы `nav.*`, `legal.*`, `notFound.*` на трёх языках.

*О проверке паритета ключей.* Отдельный скрипт не понадобился: словарь объявлен
как `Record<Locale, Dictionary>`, и TypeScript не даст собрать локаль с недостающим
ключом. Это строже скрипта — ошибка ловится компилятором, а не обходом файлов.
Для коллекций (FAQ, точки карты) класс `check:content` будет заведён с первого
дня их существования, как требует кодекс §6.

**Шаг 2 — каркас страницы.** `SiteHeader` (лого, дескриптор, переключатель языка,
тема, меню с `aria-current`), `SiteFooter` (юридические ссылки), `PageLayout`
поверх `BaseLayout` со ссылкой «перейти к содержимому».

Ссылка пропуска скрыта сдвигом, а не `display: none`: скрытый так элемент
недостижим и с клавиатуры — то есть перестал бы выполнять свою единственную задачу.

**Находка проверки границ.** Первая версия `PageLayout` импортировала словарь
напрямую — `check:conventions` поймал `layouts → data`. Починено по правилу,
а не расширением правила: словарь приходит props'ом от страницы.

**Шаг 3 — юридические страницы.** `/privacy` (включая удаление отзыва ≤7 дней)
и `/accessibility` (הצהרת נגישות) на трёх языках. Сделаны первыми осознанно:
они ни от чего не зависят, и это снимает риск «допишем перед запуском».
Компонент `LegalPage` обобщён на **второй** такой странице, не раньше (§1).

В декларации доступности прямо написано ограничение режима дислексии для иврита
(бриф §15) — до того, как сам режим написан. Так текст не окажется задним числом
подогнанным под реализацию.

**Шаг 4 — 404.** Одна страница на три языка: GitHub Pages отдаёт один файл на
любой несуществующий адрес, поэтому язык выбирается в браузере по префиксу пути,
а без JS остаётся ивритская версия — язык сайта по умолчанию.

**Улучшение проверки публичного контура.** `check:surface` проверял `noindex`
по списку из четырёх файлов — он бы молча пропустил каждую новую страницу F3.
Теперь проверяются **все** страницы в `dist`; 404 — единственное осознанное
исключение. Это ровно урок BUG-0006: полнота набора проверяется явно.

Факт:
```
npm run build → 11 страниц
✓ публичный контур: 17 файлов, страниц 11, витрины нет, noindex на месте
he /privacy/ → dir="rtl", lang="he", заголовок на иврите
```
Снимки: `docs/evidence/f3/privacy-he.png`, `accessibility-en.png`.
