# Манифест 04 — углублённый план (ревизия 2)

Дополнение к `04-static-pages.md`. Мини-план верхнего уровня остаётся; здесь
каждый оставшийся шаг разложен до уровня, на котором его можно исполнять
без дальнейших решений «по ходу». Разложено под тремя углами:
**данные** (что показывать, когда данных нет) · **взаимодействие** (мышь,
клавиатура, палец, скринридер) · **отказ** (без JS, медленная сеть, RTL,
длинные строки, узкий экран).

---

## Сквозные требования ко ВСЕМ оставшимся шагам

Эти пункты не повторяются в каждом шаге — они действуют по умолчанию,
и их отсутствие считается дефектом, а не «не успели».

1. **Три языка.** Ни одной строки в разметке. Всё через словарь; ключи —
   по неймспейсам (§3 принципов).
2. **RTL — не зеркальная копия.** Логические свойства; технические значения
   только через `TechnicalValue`; направленные иконки зеркалятся, ненаправленные нет.
3. **Клавиатура.** Каждый интерактив достижим, порядок обхода совпадает
   с визуальным, фокус виден, ловушек нет кроме намеренных (модалки).
4. **Без JS.** Страница остаётся читаемой и навигируемой. Всё, что делается
   скриптом, имеет разметочную основу: фильтры — ссылки, аккордеон — `<details>`,
   лайтбокс — обычная ссылка на изображение.
5. **Пустые данные.** Блок без данных исчезает целиком. Заглушек «скоро здесь
   будет» не бывает (бриф §4: фейки запрещены; §1: спокойный тон).
6. **Доступные имена.** Любой интерактив без видимого текста — с `aria-label`,
   обязательным на уровне типа пропсов (Норма А).
7. **Доказательство.** Снимок или вычисленный стиль, код возврата — по кодексу §6.

## Шаг 5 — Норма А: тултип и доступные имена

**5.1 Обязательность имени в типах.** Компоненты без видимого текста получают
проп `ariaLabel: string` (не `?`). Забыть нельзя — не соберётся.
*Негативный тест:* фикстура с вызовом без пропа роняет `astro check`.

**5.2 Аудит живого DOM.** В `polish-pass.mjs` — правило: перечислить поимённо
все интерактивы с пустым доступным именем. Считается по тому же алгоритму,
что и у скринридера: `aria-label` → `aria-labelledby` → текстовое содержимое →
`title`. Пусто — нарушение.

**5.3 Примитив Tooltip.**
- Разметка: цель + `<span role="tooltip" id>`; связь через `aria-describedby`
  (если у цели есть своё имя) либо `aria-labelledby` (если нет). Одновременно —
  никогда.
- Показ: `pointerenter` с задержкой 300 мс; `focus-visible` — **без задержки**
  (задержка нужна против случайного пролёта курсором, у клавиатуры пролёта нет).
- Скрытие: `pointerleave` с задержкой 100 мс (чтобы курсор успел дойти
  до подсказки — WCAG 1.4.13 hoverable), `blur`, `Escape` (dismissible).
- Не исчезает сама по таймеру (persistent).
- Позиционирование: логическое, `inset-inline-*`; при нехватке места
  переворачивается по блочной оси. Никогда не накрывает цель.
- Без JS: подсказка не показывается, но её текст остаётся в DOM для скринридера.

**5.4 Правило «без дубля».** Кнопке с видимым текстом тултип с тем же текстом
не ставится. Проверяется в аудите DOM: имя и описание не совпадают.

## Шаг 6 — Портфолио

**6.1 `/portfolio` — список.** Сетка карточек `WorkCard`. Пустой список — блок
не рендерится, вместо него один абзац приглашения написать (без «скоро здесь»).

**6.2 Фильтры — ссылками, не скриптом.**
Тип · материал · город · «есть до/после». Каждый вариант — ссылка на URL
с query, страница пререндерена под все комбинации? Нет: комбинаторный взрыв.
**Решение:** фильтрация на клиенте по `data-*` атрибутам, но **состояние в URL**
(`?type=pergola`), и при загрузке страницы фильтр применяется из URL.
Без JS видны все работы и все ссылки-фильтры ведут на тот же список —
то есть без JS сайт не ломается, он просто не фильтрует.
*Проверка:* без JS список полон; с JS фильтр меняет URL и переживает
перезагрузку; счётчик найденного озвучивается через `aria-live="polite"`.

**6.3 `/portfolio/[slug]` — паспорт.** Все фото, метрики, «что было сложным»,
отзыв (если есть и разрешён). Соседние работы внизу.
*Гейт данных:* демо-паспорт несёт маркер и на странице тоже.

**6.4 Лайтбокс.** Основа — ссылка на полноразмерное изображение (работает без JS).
С JS: диалог `<dialog>`, ловушка фокуса, Esc, возврат фокуса на миниатюру,
стрелки ←/→ между кадрами, свайп на тач. Подпись кадра всегда видима.

**6.5 «Живой чертёж» — статичная версия.** SVG-оверлей поверх cover:
габариты + 2–3 узла. Пока без анимации (F5). На тач — по тапу на иконку-угольник,
на десктопе — по hover, **и обязательно по клавиатурному фокусу**.
Деградация: если оверлея для работы нет — блок скрыт целиком.

## Шаг 7 — Услуги

**7.1 `/services`** — три карточки-входа с одной строкой сути.
**7.2 `/pergolas` `/canopies` `/fences`** — одинаковый каркас, разное наполнение:
что это · из чего делаем · что влияет на цену · работы этого типа (из коллекции,
фильтр по `type`) · вопросы · CTA.
**7.3 Анти-шаблонные блоки** (тень 12/16/19, дождь-тест, «с улицы/со двора»,
«сколько лет стоит») рендерятся **только при наличии ассета**. Реализация:
блок принимает ассет пропом; нет пропа — компонент возвращает пустоту,
а не «скоро». *Проверка:* сейчас ассетов нет → на всех трёх страницах
этих блоков нет ни одного, и это не оставляет дыр в раскладке.

## Шаг 8 — Главная, 10 экранов (бриф §3)

Каждый экран отвечает на один вопрос. Порядок и содержание — из брифа, не мои.

1. **Hero** — статичный плейсхолдер: фон-сборка (заглушка), поверх портрет
   (нет ассета → блок портрета скрыт), гео, заголовок, **две** кнопки
   (WhatsApp + «Получить предварительную оценку»), телефон вторичной ссылкой.
2. **Почему доверяют** — фото на объекте (есть 1-1.jpeg) + три конкретики,
   включая **траст-формулу дословно** из брифа §1.
3. **Последние проекты** — 3 карточки. **Показывается только при ≥3 полных
   паспортах.** Сейчас 2 демо → экран скрыт целиком. Это проверяется.
4. **Видео процесса** — фасад YouTube. Нет видео → экран скрыт.
5. **Как проходит работа** — Связь → Замер → Изготовление → Монтаж.
6. **До/После** — ползунок, 3 объекта. Нет пар «до/после» → экран скрыт.
7. **Мини-форма** — имя + телефон + кнопка. Строка согласия.
8. **Принципы мастера** — 3 реальных.
9. **FAQ** — аккордеон на `<details>`; цена и гарантия — формулы из брифа §1
   дословно.
10. **Финальный CTA** — крупное фото + три канала.

**Тизер карты** — между 6 и 7, показывается при ≥6 точках. Сейчас скрыт.

## Шаг 9 — Формы (мок-режим)

**9.1 `src/lib/api/` — единственное место сетевых вызовов.** Контракт
`/api/v1/lead` и `/api/v1/review` фиксируется здесь **сейчас**, чтобы F4
реализовывал готовый контракт, а не изобретал.
**9.2 Мок-режим** переключателем: успех · 429 · 500 · сетевой сбой.
**9.3 Состояния формы:** покой · отправка · благодарность (на месте, с кнопкой
«отправить ещё») · 429 («попробуйте через час или напишите в WhatsApp») ·
500 (сразу ветка WhatsApp).
**9.4 Honeypot и time-check** — разметка и логика на фронте уже здесь.
**9.5 Кнопка WhatsApp — всегда видима рядом с формой.** В catch — `location.href`.
**9.6 Валидация телефона:** нормализация `+972…` → `0…`, маска `^05\d{8}$`,
сообщение об ошибке человеческое.

## Шаг 10 — Sticky-панель

Появляется со второго экрана: `IntersectionObserver` на hero-сентинеле.
Без JS — панель просто видна всегда (не ломается). Не перекрывает подвал:
у `body` появляется нижний отступ ровно на высоту панели.
Конфликт с кнопкой панели доступности решается здесь же (шаг 11).

## Шаг 11 — Норма Б: панель доступности

По манифесту 05. Уточнения раскладки:
- Кнопка доступности — в противоположном инлайн-углу от sticky-панели,
  над ней по блочной оси; на мобильном sticky-панель прижата к низу,
  кнопка — над её краем.
- Состояние — один ключ `a11y` в localStorage, JSON.
- Пре-пейнт: тот же приём, что у темы, в том же inline-скрипте (один проход,
  не два).
