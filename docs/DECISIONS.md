## DEC-0001 · Astro 7.2 + Tailwind 4 через `@tailwindcss/vite`
**Дата:** 07.08.2026 · **Фаза:** F0

**Что.** Стек поставлен в текущих мажорных версиях: Astro 7.2.0, Tailwind 4.3.3.
Tailwind подключён vite-плагином, отдельного PostCSS-конфига нет.

**Почему.** Это то, что ставит `astro add tailwind` в Astro 7 — идти против дефолта
интеграции значит чинить его при каждом обновлении.

**Следствие для работы.** Astro 7 новее базы знаний Claude Code, поэтому API сверяется
по типам установленного пакета (`node_modules/astro/dist/types/`), а не по памяти.
Это правило действует на всю дальнейшую работу.

**Альтернативы.** Astro 5 + Tailwind 3 (знакомее, но сознательно устаревший старт) — отброшено.

## DEC-0002 · Базовый путь `/rabota-dom`, единственный источник — `astro.config.mjs`
**Дата:** 07.08.2026 · **Фаза:** F0 · **Решение Артура**

**Что.** До покупки домена сайт живёт на GitHub Pages как project page:
`https://arthurkomishenko-commits.github.io/rabota-dom/`.
`site` и `base` заданы в `astro.config.mjs` и больше нигде не дублируются.
В коде используются `Astro.site` и `import.meta.env.BASE_URL`; ссылки между локалями
строятся через `astro:i18n` (`getRelativeLocaleUrl` / `getAbsoluteLocaleUrl`), которые
сами учитывают base.

**Почему.** Бриф §2 требует `/` = иврит без префикса. Под project page это `/rabota-dom/`.
Переезд на домен должен быть правкой двух строк, а не ревизией всех ссылок.

**Переезд на домен** (отдельным решением позже): `site: 'https://<домен>'`, `base: '/'`,
`public/CNAME`, проверить canonical и hreflang, запись сюда.

**Альтернативы.** (а) домен сразу — отложено Артуром;
(в) отдельный репозиторий `*.github.io` ради корня — отброшено: второй репозиторий
и разрыв связи с `rabota-dom`.

## DEC-0003 · Шрифт: сабсеты Rubik лежат в репозитории, пакет — только источник
**Дата:** 07.08.2026 · **Фаза:** F0

**Что.** Три файла (`hebrew`, `cyrillic`, `latin`, variable, normal) скопированы в
`src/styles/fonts/`. `@fontsource-variable/rubik` переведён в devDependencies и служит
источником обновлений через `npm run fonts:sync`. Italic и arabic не подключены.

**Почему.** Файл в `src/` проходит через Vite: получает хэш и base в URL автоматически,
и тот же самый путь используется в `<link rel="preload">` — preload гарантированно
совпадает с тем, что запросит `@font-face`. Через `node_modules` этой гарантии нет.

**Факт бюджета:** hebrew 9.1 КБ · cyrillic 14.8 КБ · latin 34.5 КБ, при лимите 40 КБ
(бриф §2). Проверяется в CI: `npm run check:budgets`.

**Альтернативы.** Импорт CSS напрямую из `@fontsource` — тянет лишние сабсеты и italic;
`public/fonts/` — потребовал бы вручную вписывать base в `url()`, то есть вторую копию
значения вопреки DEC-0002.

## DEC-0004 · Preload только сабсета языка страницы
**Дата:** 07.08.2026 · **Фаза:** F0

**Что.** На ивритской странице предзагружается только hebrew, на русской — cyrillic,
на английской — latin. Латиница (лого «RABOTA DOM») на he/ru догружается обычным путём
с `font-display: swap`.

**Почему.** Preload обоих сабсетов на иврите — это 43.6 КБ в критическом пути ради
одной строки лого. Лого не является LCP-элементом.

**Пересмотреть,** если после F3 замеры LHCI покажут сдвиг из-за подмены шрифта в шапке.

## DEC-0005 · Диммер фото — опт-ин классом, а не глобальным селектором
**Дата:** 07.08.2026 · **Фаза:** F0

**Что.** Правило из `docs/DESIGN_TOKENS.md` записано там как
`[data-theme="dark"] img:not(:hover)`, то есть применяется ко **всем** изображениям.
Реализовано иначе — утилитой `photo-dim`, которую нужно поставить осознанно.

**Почему.** И бриф §7, и шапка самого файла токенов требуют: filter только для статичных

Значения токенов не менялись, изменён только способ применения.

**Статус.** Полная проработка внешнего вида — F1.

## DEC-0007 · Playwright для проверки гейтов
**Дата:** 07.08.2026 · **Фаза:** F0

**Что.** `playwright` (только chromium) добавлен в devDependencies.
`npm run gate:f0` снимает живой сайт на Pages и проверяет машинно: lang/dir, каскад темы,
переживание выбора после перезагрузки, отсутствие FOUC, зеркалирование логических
свойств, состав скачанных сабсетов. Скрины и JSON-отчёт — в `docs/evidence/f0/`.

**Почему.** Гейты требуют визуальных и поведенческих доказательств (протокол §7), а без
инструмента каждый такой гейт упирался бы в ожидание скринов от Артура. Дальше это же
понадобится в F1 (состояния компонентов ×2 темы ×2 направления) и в F5 (кадры сборок).
Playwright бесплатен и уже заложен в бриф §7 как фоллбек рендера OG — новая зависимость
не появляется, появляется раньше по времени.

**Важно.** Инструмент не отменяет протокол §6: проверка на **реальном устройстве**
(особенно iOS Safari, где dvh и dynamic viewport ведут себя иначе) остаётся за Артуром.
Headless Chromium — это не «проверено на телефоне».

**Альтернативы.** Расширение Claude in Chrome — не подключено в этой среде.
Ручные скрины Артура — блокируют каждый гейт ожиданием.

## DEC-0008 · Переключатель языков подписан родными названиями
**Дата:** 07.08.2026 · **Фаза:** F0 · **Решение Артура**

**Что.** «עברית · Русский · English» — каждый язык подписан на нём самом.
Коды «HE · RU · EN» отклонены.

**Почему.** Язык выбирает тот, кто НЕ читает текущий язык страницы, — значит
подпись обязана быть на целевом языке, иначе переключатель бесполезен ровно для
своей аудитории.

**Цена, принята осознанно.** На каждой странице присутствуют три письменности,
поэтому браузер скачивает все три сабсета Rubik: ≈58.4 КБ вместо ≈43.6 КБ.
Измерено `npm run gate:f0`. Бюджет «≤40 КБ на сабсет» (бриф §2) при этом
соблюдается — растёт суммарный вес страницы, а не отдельный сабсет.

**Следствие.** Preload по-прежнему только для сабсета языка страницы (DEC-0004):
латиница и третий сабсет нужны для одной короткой строки и подождут `swap`.

## DEC-0009 · `import type` разрешён через границы слоёв
**Дата:** 07.08.2026 · **Фаза:** 01b

**Что.** Проверка направления зависимостей (ARCHITECTURE_PRINCIPLES §6) пропускает
импорты вида `import type { X } from '...'`, но ловит любые импорты значений.

**Почему.** Типы не создают связи во время выполнения — после сборки от них не
остаётся ни байта. При этом §2 прямо помещает контракты (Zod-схемы и их TS-типы)
в `src/data/schemas/`, значит компонент, принимающий такой контракт в props,
обязан уметь сослаться на его тип. Запрет здесь заставил бы дублировать формы
данных руками — это хуже, чем связь, которой нет в рантайме.

**Проверено.** Самотест: `components → data` обычным импортом ловится
(`npm run check:selftest`, кейс «components → data»), тип-импорт проходит.

## DEC-0010 · Полировочный проход поднимает свой статический сервер
**Дата:** 07.08.2026 · **Фаза:** 01b

**Что.** `scripts/polish-pass.mjs` раздаёт собранный `dist/` собственным
30-строчным сервером на случайном порту вместо `astro preview`.

**Почему.** В Astro 7 `astro preview` — фоновый демон: он переживает завершение
процесса, при повторном запуске игнорирует `--port` и отвечает «already running»
на другом порту. Прогон полировки становился недетерминированным и однажды уже
дал ложное падение. Управлять жизненным циклом чужого демона ради теста — лишняя
хрупкость; отдать статику самому проще и надёжнее.

**Следствие.** Полировочный проход не зависит от состояния машины и может
запускаться в CI.

## DEC-0011 · Витрина `/__ui/` не существует в production-сборке
**Дата:** 07.08.2026 · **Фаза:** F1 · **Требование Артура**

**Что.** Витрина живёт в `src/showcase/`, а её маршрут инжектится интеграцией
`rabota-dom:ui-showcase` только при `UI_SHOWCASE=1`. В обычной сборке маршрута
`/__ui/` не существует: в `dist/` нет ни файла, ни ссылки.

**Почему выбран этот способ, а не «noindex + скрыть».** Спрятать существующую
страницу нужно было бы в четырёх независимых местах — sitemap, hreflang,
навигация, robots. Каждое из них однажды забыли бы, и витрина уехала бы в
публичный контур молча. Несуществующий маршрут прятать не нужно.

**Как открыть:** `npm run dev` или `npm run build:ui` (сборка с витриной
печатает предупреждение, что она не для публикации).

**Гарантия, а не намерение.** `npm run check:surface` проверяет собранный `dist/`
после каждой сборки и падает, если витрина туда попала; заодно требует `noindex`
на всех публичных страницах (DEC-0006). Проверка встроена в `npm run build`,
значит работает и в CI.
Негативный тест выполнен: сборка с `UI_SHOWCASE=1` → `✗ запрещённый маршрут
в публичной сборке: dist/__ui/index.html`, exit=1.

**Страховка сверх этого.** `/__ui` добавлен в `NON_LOCALIZED_PREFIXES`, поэтому
даже в showcase-сборке hreflang для него не генерируется, и страница несёт `noindex`.

## DEC-0012 · Контраст AA: `--accent-text`, затемнение `--text-muted`, опознание поля
**Дата:** 08.08.2026 · **Фаза:** F1, шаг 7 · **Решение Артура** ·
**Ревизия `docs/DESIGN_TOKENS.md` согласована владельцем файла**

**Основание.** Замеры `npm run check:contrast` (значения читаются из
`variables.css`, не из копии в скрипте). В светлой теме не проходили три
текстовые пары; тёмная тема проходила целиком.

**Что решено.**
1. Введён **`--accent-text`**: светлая `#98461A`, тёмная `#E07A3E` (тот же цвет —
   акцент там уже проходит AA как текст). `--accent-wood` **не тронут** и остаётся
   для кнопок, фокус-колец и крупных элементов.
   Правило употребления: любой сплошной текст акцентом — только `--accent-text`.
2. **`--text-muted`** светлой темы затемнён `#64748B` → `#5F6B80`.
   Вариант «использовать вторичный текст только на поверхности» отклонён Артуром
   как хрупкий: подписи на фоне страницы неизбежны.
3. **Опознание поля ввода** повешено на нижнюю «линию чертежа», а не на рамку.

**Почему именно так, а не иначе.** Условие Артура было: правило употребления
в приоритете, новый токен — только если реальное употребление без него не проходит.
Проверено буквально: вторичный CTA «Позвонить», текст ошибки поля и ссылки
в карточках — это мелкий сплошной текст, и цвет там несёт функцию. Вариант
«убрать акцент из текста» лишал CTA опознаваемости, а ошибку — сигнальности.
Вариант «взять `--accent-wood-hover`» проходил по цифрам (6.02), но приравнивал
обычное состояние к наведённому и убивал отклик ссылки на курсор.

**Факт после правки** (`npm run check:contrast`, exit=0):
```
светлая: акцентный текст 6.08 / 6.51 · вторичный текст 5.03 / 5.38
         линия чертежа поля 5.38 · в фокусе 4.27 · фокус-кольцо 3.99 / 4.27
тёмная:  акцентный текст 6.17 / 5.65 · вторичный текст 7.20 / 6.58
         линия чертежа поля 6.58 · в фокусе 5.65 · фокус-кольцо 6.17 / 5.65
✓ все пары проходят AA
```
Проверка подключена к `npm run check`, `npm run build` и к CI.

**Поправка к самой проверке, а не к порогу.** Первая версия требовала 3:1 от любой
границы. Это неверно: WCAG 1.4.11 требует 3:1 от того, что необходимо для опознания
элемента управления, — декоративная рамка карточки под это не подпадает. Порог не
ослаблен, он предъявлен там, где применим: заливка поля отличается от страницы
всего на 1.07, значит поле опознаёт линия, и требование адресовано ей.
Декоративная рамка и заливка выводятся справочно, без порога.

## DEC-0013 · Сырьё контента — `content/works/work-NN/`, одна папка на объект
**Дата:** 08.08.2026 · **Фаза:** F2 · **Предложение Артура, уточнено по пайплайну**

**Что.** Паспорт, фото и локализованные записи одной работы лежат в одной папке
в корне проекта:
```
content/works/work-NN/
  intake.md              не публикуется, источник для записей
  photos/*.jpg           оригиналы, 1600–2400px по длинной стороне, ≤1.5 МБ
  he.mdx ru.mdx en.mdx   записи коллекции, Zod-гейт
```
Коллекция подключается loader'ом `glob({ base: './content/works', … })`
в `src/content.config.ts`; изображения объявляются через `image()` в схеме,
поэтому путь получает хэш и base автоматически.

**Почему не `src/assets/raw/works/`** (исходное предложение Артура).
Сама идея «одна папка на объект с `intake.md`» принята — изменено только место.
1. `src/assets/` — namespace, из которого Astro берёт картинки при импорте.
   Сырьё там соседствует с публикуемым: можно случайно импортировать в страницу
   многомегабайтный оригинал, а проверка бюджетов не отличит вход пайплайна
   от того, что грузит посетитель.
2. В Astro 7 контент не обязан лежать в `src/content/`: у loader'а `glob`
   параметр `base` отсчитывается от корня проекта (проверено по типам
   установленного пакета, не по памяти). Значит паспорт, фото и записи можно
   держать вместе — ровно той единицей, которой контент и собирается.
3. Производные (WebP/AVIF нужных размеров) в репозиторий не попадают вообще:
   создаются при сборке, живут в `dist/`. Гейт F9 «репозиторий не растёт
   неоптимизированными файлами» выполняется по построению.

**Границы оригиналов: 1600–2400px, ≤1.5 МБ.** Нижняя — из требований шаблона
(ниже не хватит на retina-карточку), верхняя — чтобы в git не оседал мёртвый
вес, который всё равно ужимается при сборке. Проверяется `check:budgets` в F2.

**Тестовые фикстуры схемы** (решение Артура): только явно помеченные
и непубликуемые. Помечаются признаком в записи; `check:surface` уже ловит
попадание непубликуемого в `dist/`, для фикстур правило дополняется в F2.

## DEC-0014 · Демо-контент до выездной сессии · ревизия брифа v2.1 §13
**Дата:** 09.08.2026 · **Фаза:** F2 · **Решение Артура**

**Что.** Реальный контент придёт одним пакетом примерно через месяц. Производство
не ждёт: строится на демо-паспортах, которые пишет Claude Code по
`docs/INTAKE_TEMPLATE.md` как за мастера.

**Правила, отличающие демо от подделки.**
- Признак `demo: true` — машинный, в схеме, фильтруемый и проверяемый.
- Демо **видно** в staging: явный маркер на карточке и на странице. Спутать
  с реальным нельзя ни на скрине, ни на живой странице.
- Фото — только `1-1.jpeg` и нейтральные чертёжные заглушки, сгенерированные
  нами. Изображения из интернета запрещены категорически, даже «для теста».
- **Демо-отзывы не создаются вообще.** Выдуманный отзыв реального человека —
  это не заглушка, а подделка; помеченная подделка остаётся подделкой.

**Гейт.** `check:freeze` падает при наличии хоть одной `demo`-записи, при
`rates.status: draft` и при числе полных паспортов < 8. Обычный CI при демо
остаётся зелёным: демо-режим ничего не ослабляет, он отодвигает гейты до фриза.

**Следствие для схемы.** Схема, написанная под демо, имеет право быть переписана
реальными паспортами — это штатный возврат к шагу 2 манифеста 03, не откат.

## DEC-0015 · Норма А: тултипы и доступные имена · ревизия брифа v2.1 §14
**Дата:** 09.08.2026 · **Фаза:** F1 (примитив) → все · **Решение Артура**

**Что.** Интерактив без видимого текста обязан иметь доступное имя; отсутствие
ловится машинно. Вводится единый примитив `Tooltip`: hover **и** клавиатурный
фокус, задержка ~300 мс, Esc, не перекрывает цель, RTL-aware, WCAG 1.4.13.

**Почему это не «просто подсказка».** Тултип, работающий только на наведении, —
это функциональность, недоступная с клавиатуры и с тач-устройства. Поэтому
критичная информация не живёт только в тултипе, а кнопке с видимым текстом
дубль-тултип не ставится: вторая озвучка того же текста мешает скринридеру.

**Где реализуется.** Дополнением к дизайн-системе — манифест `02b-tooltip.md`.
Проверка доступных имён — типами пропсов и полировочным проходом на живом DOM.

## DEC-0016 · Норма Б: собственная панель доступности · ревизия брифа v2.1 §15
**Дата:** 09.08.2026 · **Фаза:** F3 · **Решение Артура**

**Что.** Своя лёгкая панель, десять режимов, кнопка у нижнего края.
Сторонние виджеты-скрипты **запрещены**.

**Почему своя.** Готовые оверлеи доступности навешивают чужой скрипт на все
страницы, ломают собственную клавиатурную навигацию и работают поверх разметки,
а не вместе с ней. У нас уже есть система токенов и каскад тем — режимы ложатся
на неё классами и переменными на `<html>`, без второй системы стилей.

**Честная оговорка, которая пойдёт в декларацию.** Свободного шрифта для
дислексии, покрывающего иврит, не существует. Режим покрывает латиницу
и кириллицу; для иврита компенсация идёт размером и интервалами, и об этом
сказано прямо, а не умолчано.

**Где реализуется.** Отдельный манифест в F3 (`05-accessibility-panel.md`),
отражено в `docs/PLAN.md`. Все режимы входят в полировочный чек-лист каждой
страницы, а не проверяются один раз при сдаче панели.

## DEC-0017 · Режим автономного марафона · ревизия протокола v2.1 §14
**Дата:** 10.08.2026 · **Решение Артура**

**Что.** Работа идёт непрерывно F3 → F8 (+подготовка F9) без остановок на
вопросы. Обратимые решения принимаются самостоятельно с пометкой **[AUTO]**;
необратимые уходят в `docs/QUESTIONS_FOR_ARTUR.md`, и работа продолжается тем,
что от них не зависит. Блокеры превращаются в подготовку: код Worker на моках,
анимационная система с черновой hero-сборкой, `rates.json` в draft.

**Что режим НЕ меняет.** Планка. Мини-планы до кода, гейты, полировочные проходы,
негативные тесты, доказательства — всё действует в последней фазе так же, как
в первой. Непрерывность не равна спешке: скорость по-прежнему не критерий
(QUALITY_DOCTRINE §0). Ни один гейт не снижается ради того, чтобы «пройти дальше».

**Почему это безопасно именно здесь.** К моменту старта марафона уже собран
контур, который ловит ошибки без участия человека: 21 негативный тест на правила,
границы слоёв, бюджеты, контраст, целостность контента, публичный контур,
полировочный проход. Автономия опирается на эти проверки, а не на самоуверенность.

**Граница, которую я держу отдельно.** Демо-правила не ослабляются: ничего
похожего на реальные данные. Тексты страниц — реальная копия по EDITORIAL.md
со статусом «до вычитки мастером», демо-маркер носят только данные работ.

## DEC-0018 [AUTO] · Тексты страниц F3 — реальная копия, не демо
**Дата:** 10.08.2026 · **Уточнение Артура, зафиксировано**

**Что.** Заголовки, FAQ, принципы и политики пишутся как **реальная копия**
по EDITORIAL.md со статусом «до вычитки мастером». Демо-маркер на них не ставится:
его носят только данные работ (бриф §13).

**Почему.** Маркер «демо» на тексте страницы обесценил бы сам маркер: если им
помечено всё подряд, он перестаёт различать выдуманные работы и живой текст.
Статус текста — это не пометка на странице, а состояние в документах: вычитка
мастером входит в Content Freeze.

**Формулы-заглушки** (траст-формула, ценовая честность, гарантия) берутся
из брифа §1 **дословно** и не перефразируются.

## ОТКРЫТО · Пайплайн изображений: astro:assets или свой sharp-скрипт · решать в F2/F3
**Дата:** 08.08.2026 · **Фаза:** F2 → F3

Бриф §2 предписывает pre-build скрипт на sharp (raw → WebP/AVIF, responsive,
жёсткие бюджеты, билд падает при превышении). При этом в Astro 7 встроенный
сервис изображений работает на том же sharp и умеет responsive-варианты,
а `image()` в схеме коллекции даёт типизированную ширину/высоту и хэш пути.

Два пайплайна на одну задачу — это тот самый дублирующий шов, который
ARCHITECTURE_PRINCIPLES §1 велит не заводить. Нужно выбрать один.

**Вариант А — встроенный сервис Astro.** Меньше своего кода, бюджеты проверяются
отдельной проверкой по `dist/`. Риск: меньше контроля над точным набором ширин
и форматов, чем описано в брифе.
**Вариант Б — свой sharp-скрипт, как в брифе.** Полный контроль и падение
сборки при превышении по построению. Цена: свой код, который придётся вести.

Решение принимается на шаге изображений в F2/F3 — **не сейчас**: до появления
первых реальных фото выбор был бы гаданием. Токены и схемы от него не зависят.

## ОТКРЫТО · Читаемость «спила» зависит от кадра · решать в F3 при отборе фото
**Дата:** 08.08.2026 · **Фаза:** F1 → F3 · **отложено по согласованию с Артуром**

**Факт.** «Спил» карточки — срез внешнего верхнего угла фото — читается только
там, где содержимое кадра контрастирует с поверхностью карточки. На одном и том
же фото в LTR срез виден белым треугольником по небу, а в RTL приходится на белую
стену и полностью сливается. Геометрия при этом верна и зеркалится (проверено
вычисленным `clip-path`).

**Почему не чинил.** Добавить грань среза (хайрлайн вдоль диагонали) — это
изменение языка дизайна, которого нет в брифе §4. Молча вводить его нельзя.

**Варианты к F3:** (а) требование к кадрам — верхний внешний угол не должен быть
светлой заливкой; (б) хайрлайн `1px` вдоль среза токеном `--border-metal`;
(в) оставить как есть, считая срез «тихой» деталью.

## ЗАКРЫТО 07.08.2026 (см. DEC-0008) · Переключатель языков тянет все три сабсета
**Дата:** 07.08.2026 · **Фаза:** F0

**Факт (измерено, `npm run gate:f0`).** На каждой из трёх локалей браузер скачивает
**все три** сабсета: hebrew + cyrillic + latin ≈ 58.4 КБ. Ожидание манифеста
(«грузится только нужный сабсет») не выполняется.

**Причина — не ошибка настройки.** `unicode-range` работает верно: на странице физически
присутствуют все три письменности, потому что переключатель языков подписан на родных
языках («עברית · Русский · English»), а лого «RABOTA DOM» — латиницей.

**Развилка.**
(а) оставить родные названия — честнее и доступнее для пользователя, цена +14.8 КБ
на ивритской странице (кириллица ради одного слова «Русский»);
(б) подписать коды «HE · RU · EN» — латиница уже нужна для лого, ивритская страница
экономит cyrillic-сабсет; цена — менее очевидный переключатель;
(в) гибрид: коды в шапке, родные названия в подвале или в меню.

**Решено:** вариант (а), родные названия — DEC-0008.
