# Worker — приём заявок и отзывов

Отдельный сервис. Живёт своим циклом: сайт и Worker деплоятся независимо,
их связывает только версионированный контракт `/api/v1/*`
(ARCHITECTURE_PRINCIPLES §2).

## Что он делает

- `POST /api/v1/lead` — заявка: имя, телефон, город и комментарий по желанию.
- `POST /api/v1/review` — отзыв: имя, текст, обязательное согласие на публикацию.

Обе точки: ловушка для ботов, проверка времени заполнения, ограничение частоты
по IP (5 в час), нормализация телефона, CORS только нашему домену, отправка
в Telegram **без `parse_mode`** и ответ клиенту до завершения отправки.

## Секретов в репозитории нет

Токен и `chat_id` не лежат в коде, в конфиге и в истории. Они кладутся один раз
командами ниже и хранятся на стороне Cloudflare.

## Инструкция для Артура — пошагово

Всё выполняется один раз. Порядок важен: KV должен существовать до первого
деплоя, иначе Worker не поднимется.

### Шаг 1. Бот и chat_id

1. В Telegram открыть **@BotFather** → `/newbot` → задать имя и юзернейм.
2. BotFather пришлёт **токен** вида `1234567890:AA...`. Никому не пересылать,
   в чат со мной тоже не вставлять — он нужен только на шаге 4.
3. Написать своему боту любое сообщение (иначе он не сможет писать первым).
4. Узнать `chat_id`: открыть в браузере
   `https://api.telegram.org/bot<ТОКЕН>/getUpdates` и найти в ответе
   `"chat":{"id":123456789`. Это число — `chat_id`.

Если бот будет писать не тебе, а Владимиру — сообщение боту должен отправить
он, и `chat_id` будет его.

### Шаг 2. Cloudflare и вход в CLI

```bash
npm i -g wrangler          # если ещё не стоит
wrangler login             # откроет браузер, нужен аккаунт Cloudflare
```

### Шаг 3. Хранилище для ограничения частоты

```bash
cd worker
wrangler kv namespace create RATE_LIMIT_KV
```

Команда выведет строку вида `id = "abc123..."`. Этот id нужно вписать
в `worker/wrangler.toml` вместо `PLACEHOLDER_KV_ID`.

### Шаг 4. Секреты

```bash
wrangler secret put TELEGRAM_TOKEN     # вставить токен из шага 1
wrangler secret put TELEGRAM_CHAT_ID   # вставить chat_id из шага 1
```

Обе команды спросят значение в консоли и никуда его не запишут на диске.

### Шаг 5. Разрешённые источники

В `worker/wrangler.toml` в `[vars]` указать адрес сайта:

```toml
ALLOWED_ORIGINS = "https://arthurkomishenko-commits.github.io"
```

После переезда на домен сюда добавляется он — через запятую, старый адрес
можно оставить на время переезда.

### Шаг 6. Деплой

```bash
wrangler deploy
```

В выводе будет адрес вида `https://rabota-dom-api.<аккаунт>.workers.dev`.
**Этот адрес нужно вписать в `src/lib/api/client.ts`** в константу `API_BASE` —
пока она пустая, сайт работает на моках и никуда не отправляет.

### Шаг 7. Проверка (гейт F4 брифа)

1. Открыть сайт, заполнить форму, отправить.
2. Сообщение должно прийти в Telegram.
3. Прислать скрин сообщения — это и есть доказательство гейта.

Если не пришло — `wrangler tail` покажет живой лог Worker'а.

## Локальная разработка

```bash
cd worker
wrangler dev              # поднимет Worker локально
npm run test:worker       # тесты на моках, без сети и секретов
```

Тесты не требуют ни токена, ни аккаунта: внешние вызовы подменяются.

## Почему без `parse_mode`

С разметкой Telegram отвечает ошибкой на любое имя со звёздочкой или
подчёркиванием, и заявка теряется молча. Цена «красивого форматирования» —
потерянный клиент. Структуру даёт эмодзи и переносы строк.
Запрет зафиксирован в протоколе §10 и в брифе §2.
